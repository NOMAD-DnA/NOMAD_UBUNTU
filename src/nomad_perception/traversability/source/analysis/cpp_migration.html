기준 nomad-pi5-oak-zed-native-20261105-7을 보존하고 새 실행 패키지 nomad-costmap-cpp-20261105-1을 만들었다. 수신, 지도 계산, 상태 감시, 실행 관리와 런처를 C++로 전환했다. PC 가상 센서와 시험 기록기 및 실시간 웹 화면은 Python과 JavaScript를 유지한다.

실물 Jetson에 설치하거나 센서를 연결해서 검증하지 않았다. ARM64 시험은 기존 Jetson 계열 rootfs의 QEMU 환경이다. 최대 지도 수신 간격 1초를 보장하지 않는다. 기준 -7과 실제 Jetson 설치본 -1은 교체하지 않았다.

변환 중 주의한 차이

수치 계산과 순서

NumPy/LAPACK의 고유값 계산을 Eigen으로 바꾸면 부동소수점 반올림과 연산 순서에 따른 차이가 생길 수 있다. fast-math와 FMA 수축을 끄고 nearest-even 반올림 및 나노초 정수를 사용했다. 관측 순서와 같은 우선순위 클래스의 동률 처리도 따로 맞췄다.

시험 입력에서는 셀 판정과 유효 마스크를 비교하고 각 연산의 수치 허용 오차를 검사한다. 모든 가능한 입력에서 Python과 비트 단위로 같다고 주장하지 않는다. 경계값 근처의 실제 센서 기록을 추가 대조할 여지는 남아 있다.

실행과 빌드

ROS의 C++ 메시지 생성과 ament 빌드 도구는 Python을 쓴다. 이는 사용자가 허용한 빌드 단계다. 배포 실행은 감독기가 C++ ELF를 직접 시작하며 Python 런처, ros2 run, ros2 launch와 setup 스크립트를 호출하지 않는다.

Humble의 CMake 내보내기에 연결된 불필요한 Python 메시지 바인딩은 이 프로젝트의 C++ 링크 대상에서 제외했다. ROS 설치 자체를 수정하지 않았다. 배포 파일의 동적 의존성과 실행 중 프로세스의 로드된 라이브러리도 검사한다.

근거: Goldberg의 부동소수점 원문, NumPy eigh의 LAPACK 사용 문서, ROS 2 Humble C++ 메시지 생성기 원본. 전용 수신 프로세스 분리는 기존 -7의 구조를 C++로 옮긴 것이다.

Jetson에서 직접 빌드하고 실행

Jetson에는 jetson_costmap_cpp_source_20261105_1.tar.gz를 올린다. 기존 ROS 2 Humble 개발 환경과 g++, CMake, Eigen3 및 OpenSSL 개발 헤더가 필요하다. 소스와 vendor 라이브러리 및 LiDAR SDK/드라이버 원본을 묶었다. Python은 빌드에서만 사용한다.

tar -xzf jetson_costmap_cpp_source_20261105_1.tar.gz
cd costmap_cpp_source_20261105_1
./build_on_jetson.sh

runtime-jetson/lib/nomad_costmap_cpp/nomad_runtime_manager --action check
runtime-jetson/lib/nomad_costmap_cpp/nomad_runtime_manager --action start --run-id cpp_01
runtime-jetson/lib/nomad_costmap_cpp/nomad_runtime_manager --action status --run-id cpp_01
runtime-jetson/lib/nomad_costmap_cpp/nomad_runtime_manager --action stop --run-id cpp_01

기본 ROS 경로는 /opt/ros/humble/install, ROS_DOMAIN_ID는 42다. 기존 LiDAR USB by-id 경로를 사용한다. 필요하면 --ros-prefix, --lidar-port로 지정한다. 빌드 ROS 경로는 NOMAD_ROS_PREFIX, 병렬 작업 수는 NOMAD_BUILD_JOBS로 바꾼다. 기본 빌드 작업 수는 2다.

새 출력은 runtime-jetson이며 기존 배포 폴더를 자동 교체하지 않는다. 재빌드 출력은 NOMAD_RUNTIME_DIR로 새 경로를 지정한다. 상태와 로그는 실행 폴더의 runs/실행ID에 남긴다. 이 실행 관리기는 전환 전 Python 감독기 JSON 설정을 읽는 호환 런처가 아니므로 위 C++ 실행 명령을 사용한다.

기존 시험 명령

cd costmap_benchmark_20261105
python3 run.py --pc-native --duration 60 --hz 5 --points 6000 --faults all

이 명령의 기본 지도 모듈은 이제 C++다. PC에는 검증한 C++ 런타임 costmap_cpp_20261105/release/pc-cpp-1을 사용한다. 이전 Python 기준본은 다음처럼 명시해서 재시험한다.

python3 run.py --pc-native --mapper python-reference --duration 60 --hz 5 --points 6000 --faults all

이번 C++ 실행의 실시간 화면과 기록 재생에서 상단 빌드 ID, 차량 위치와 전체 맵, 의미 비용, 경사 비용, 합성 지도 및 입력 상태를 확인할 수 있다. 별도 실행의 기본 웹 포트는 8766이며 이미 사용 중이면 실제 할당된 주소가 터미널에 표시된다.

남은 실제 검증

실물 Jetson에서 소스 빌드, 실제 LiDAR 장치 연결, Pi5 및 의미분할 모듈의 실제 토픽과 시간 및 TF 계약을 확인해야 한다. 최종 패키지는 ROS C++ underlay와 시스템 공유 라이브러리를 사용하는 방식이며 ROS와 OS까지 포함한 독립 설치 이미지가 아니다.

프로세스 소유권은 PID, 시작 시각, 부팅 ID와 그룹 ID로 확인한다. ARM64 QEMU가 자기 /proc stat에 그룹 0을 보고한 문제를 발견하여 Linux getpgid 원본 문서에 따른 커널 호출로 그룹을 조회하고 자식의 전용 그룹 준비도 확인하도록 수정했다.

일반 종료와 지도 프로세스 장애, 중복 시작, 오래된 PID 소유권, 초기 준비 시간 초과와 해시 변조를 검사했다. 모든 OS 강제 종료와 하드웨어 장애 조합을 검증한 것은 아니다. CPU만 사용한다는 조건도 패키지의 실행 의존성 범위이며 별도 의미분할 모듈의 구현 방식은 이 전환 범위에 포함되지 않는다.

기준본과 검증 기록은 보존한다. 최신 선택 기록은 최종_비용지도_모듈_기준_20261105.txt의 C++ 전환 항목을 따른다.
