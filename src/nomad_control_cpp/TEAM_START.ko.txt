NOMAD 팀 통합 실행 — 2026-11-09

최신 소스는 이 폴더의 nomad_control_cpp-integrated-20261109.tar.gz입니다.
팀 ROS workspace의 src 아래에 nomad_control_cpp 폴더를 넣으세요.
이후 workspace 루트에서 아래 한 줄로 실행합니다.

bash src/nomad_control_cpp/scripts/start_lpp.sh

자동 처리: 증분 빌드, LPP 컴파일 활성화, install 환경 로드, 보정표/헤드리스/기존 NOMAD 차량 준비 프로필 로드.
GUI, 별도 YAML 편집, 보정 플래그 편집, GUI heartbeat는 필요하지 않습니다.
빌드 실패 시 이전 실행본을 대신 실행하지 않고 실패 내용을 표시합니다.

이미 빌드한 통합 launch에는 다음 진입점을 포함하면 됩니다.
ros2 launch nomad_control_cpp lpp.launch.xml
XML launch에서는:
<include file="$(find-pkg-share nomad_control_cpp)/launch/lpp.launch.xml"/>

남아 있는 실제 연결 전제
- ROS Humble, colcon, 팀 nomad_interfaces와 vesc_msgs 의존성이 설치/빌드되어 있어야 합니다.
- 기존 VESC 드라이버는 팀 bringup이 실행합니다. 이 실행기는 드라이버를 중복으로 띄우거나 다른 제어기를 강제 종료하지 않습니다.
- 드라이버 토픽은 기존 NOMAD의 /nomad_bench/sensors/core와 /nomad_bench/commands/... 구성입니다.
- LPP와 제어기의 DDS domain/네트워크가 같아야 합니다. 다른 장치 연결 시 localhost-only를 해제해야 합니다.
- 같은 VESC에 출력하는 제어기는 하나여야 합니다. 소스/실행기만으로 다른 팀의 토픽 구조까지 추측해 바꾸지는 않습니다.
- 기존 NOMAD 차량의 확인된 VESC 준비 설정을 포함합니다. 다른 차량/VESC에 그대로 사용하지 마세요.

입력: /nomad/planning/drive_command, nomad_interfaces/msg/DriveCommand.
0~0.25 m/s, ±0.3 rad, base_link, 최신 stamp, valid_for 0.3초, 권장20~50Hz.
유효 명령 수신 시 자동 시작합니다. 현재 사진/영상 초기 보정표로 실행하며 실측 검증 완료 플래그는 유지하지 않고 false입니다.
STOP 또는 명령 만료 후 자동 재출발하지 않습니다. 원인 해결 후 /nomad_vesc_trial/reset으로 다시 준비하세요.
기존 GUI 수동 모드는 기존 실행 방식 그대로 사용할 수 있습니다. LPP 전용 모드와 동시에 출력하지 않습니다.

이 배포는 소스와 자동 실행 구성입니다. 팀의 실제 통합 launch/실행 환경은 제공받지 못해 직접 연결 검증하지 못했습니다.
WSL ROS의 가짜 VESC 통합 검사는 통과했습니다. 실제 Pi 운영본을 이 버전으로 자동 교체하거나 차량을 구동하지 않았습니다.
