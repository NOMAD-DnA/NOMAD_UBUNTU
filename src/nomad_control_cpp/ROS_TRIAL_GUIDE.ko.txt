NOMAD C++ VESC telemetry 확인 / 시간 제한 구동 시험

수동 GUI가 추가되었습니다. SSH 주소 확인, GUI 연결과 공중 시험 순서는 GUI_GUIDE.ko.txt를 읽으세요.

1. 구현 범위

src/controller_node.cpp는 ROS 2 Humble 노드입니다.
src/trial_controller.cpp는 ROS 없이도 시험할 수 있는 상태·정지 판단 코드입니다.
기존 src/vesc_mapping.cpp를 호출해 m/s·등가각을 ERPM·서보값으로 바꿉니다.

이 노드는 LPP DriveCommand를 받는 자율주행 제어기가 아닙니다.
설정한 고정 목표 또는 수동 GUI 목표로 짧은 시험을 수행하며, 기본 모드는 monitor입니다.
기존 VESC 드라이버는 재사용하고 USB 장치를 직접 열지 않습니다.

monitor:
  실제 telemetry 수신, 속도 환산, 목표 변환 미리보기, 상태 출력만 수행합니다.
  모터·서보 명령 publisher를 아예 만들지 않습니다. stop을 호출해도 장치 출력은 없습니다.
  calibration_verified=false일 때 환산속도·미리보기는 가상 계수 기반임을 표시합니다.
bench:
  실행만으로는 어떤 장치 명령도 보내지 않습니다.
  조건 확인 후 start_test 서비스를 호출해야 1회의 시험이 시작됩니다.
  시험 시간은 조향 준비를 포함해 최대 5초입니다. 중복 start로 연장되지 않습니다.

2. 파일과 설정

src/controller_node.cpp: ROS 구독, publisher, 서비스, 주기 실행 (nomad_controller_core 라이브러리)
src/controller_main.cpp: 실행 진입점, Ctrl+C/SIGTERM 시 정지 출력 후 정상 종료 처리
include/nomad_control_cpp/controller_node.hpp: 노드 생성(ControllerNode::create)과 종료 준비 인터페이스
include/nomad_control_cpp/trial_controller.hpp: 시험 설정·telemetry·상태 자료형
src/trial_controller.cpp: 시작 조건, 시간 제한, 정지·fault, 출력 변화율
config/controller.yaml: ROS 실행 설정. 기본 비구동, 미보정 상태
test/test_trial.cpp: 가짜 시각·telemetry로 상태 머신을 검사
test/test_controller_ros.cpp: 고유 시험 namespace의 가짜 VESC로 실제 ROS IO를 검사

ROS 노드는 controller.yaml의 calibration.* 값을 사용합니다.
오프라인 nomad_convert는 여전히 config/calibration.hpp를 사용합니다.
ROS 파라미터를 생략하면 헤더 계수가 기본값이지만, 제공 YAML은 모든 계수를 명시합니다.
실차 보정값은 ROS용 YAML에 먼저 반영하세요. 오프라인 계산도 같은 값으로 비교하려면
헤더도 맞춰야 합니다. YAML 변경은 노드 재시작으로 적용되며 재컴파일은 필요 없습니다.
실행 중 ROS 파라미터 변경은 차단합니다. GUI는 별도 검증 서비스로 목표를 바꾸며 시험 시간을 연장하지 않습니다.

3. Pi 4에서 별도 작업공간으로 빌드

기존 nomad_link_ws와 vesc_ws를 덮어쓰지 않고 다음 위치를 권합니다.
  /home/user/nomad_cpp_ws/src/nomad_control_cpp

Windows 프로젝트에서 build, build-*, install, log 폴더를 제외하고 복사하세요.
Pi 4에 ROS Humble 개발 환경, colcon, 기존 vesc_msgs가 필요합니다.

source /opt/ros/humble/setup.bash
source /home/user/vesc_ws/install/setup.bash
cd /home/user/nomad_cpp_ws
colcon build --packages-select nomad_control_cpp --cmake-args -DNOMAD_BUILD_ROS2=ON
source install/setup.bash

ROS가 없는 PC의 기존 오프라인 빌드는 그대로 지원됩니다.
cmake -S . -B build -DNOMAD_BUILD_ROS2=OFF
cmake --build build
ctest --test-dir build --output-on-failure

4. ROS 가짜 장치 통합 시험 (실차 출력 없음)

Pi/ROS 환경에서 빌드한 뒤:
cd /home/user/nomad_cpp_ws
colcon test --packages-select nomad_control_cpp --event-handlers console_direct+
colcon test-result --verbose

controller_ros_integration은 /nomad_cpp_test_<고유값>/ 아래에 가짜 telemetry,
모터·서보 수신기와 시험 노드를 만듭니다. 실제 /commands 또는 /sensors를 사용하지 않습니다.
monitor의 publisher 부재, 수동 시작, 시간 만료, stop, telemetry 단절을 검사합니다.
다른 작업의 실제 VESC를 켤 필요가 없습니다.

5. 실제 telemetry만 확인

기존에 검증한 VESC 드라이버를 실행하고, 같은 ROS_DOMAIN_ID를 사용합니다.
실제 토픽에 namespace가 있으면 controller.yaml의 *_topic 값을 모두 맞추세요.
run_pi4_vesc_cycle.sh는 기존 Python Control도 시작하는 기록이 있으므로
C++ 구동 시험과 함께 실행하지 마세요. 드라이버만 별도로 실행해야 합니다.

ros2 topic list -t
ros2 topic echo /sensors/core --once

ros2 run nomad_control_cpp controller_node --ros-args \
  --params-file /home/user/nomad_cpp_ws/src/nomad_control_cpp/config/controller.yaml

다른 터미널에서:
ros2 topic echo /nomad_vesc_trial/status

주요 상태:
  state=MONITOR                 장치 출력 없는 확인 모드
  telemetry_fresh=1            stamp와 실제 수신 경과 시간이 모두 유효
  calibration_verified=0      환산 계수가 실측 검증으로 표시되지 않음
  raw_erpm                     VESC의 마지막 raw 회전수
  speed_mps                    보정식으로 환산한 마지막 속도
  preview_erpm/preview_servo   목표를 변환했을 때의 계산값 (실제 송신값 아님)
  stationary=1                최신 ERPM/환산속도가 정지 문턱 안에서 설정 시간 유지
  steering_measured=false     실제 조향각 센서를 사용하지 않음

telemetry_fresh=0인 경우 표시된 마지막 숫자를 현재 측정값으로 사용하지 않습니다.
VESC 드라이버 stamp는 드라이버 수신 시각이지 모터 내부 측정 시각을 증명하지 않습니다.
필요하면 ros2 topic info <명령토픽> --verbose로 이 노드가 monitor에서
모터·서보 publisher를 만들지 않는 것도 확인할 수 있습니다.

6. 구동 시험 준비

controller.yaml의 다음 항목을 실차에 맞춰 설정합니다.
  calibration.*                실제 측정하고 별도 검증한 계수·부호·범위
  target_speed_mps             시험 목표 속도 (기본 0)
  target_steering_rad          시험 목표 등가 조향각 (기본 0)
  trial_duration_s             조향 준비 포함 시험 시간, 0 초과 5 이하
  acceleration_mps2            속도 명령 변화율
  steering_rate_radps          등가 조향 명령 변화율
  steering_settle_s            명령각 도달 뒤 대기 시간
  stationary_erpm              실제 정지 잡음으로 확인한 ERPM 문턱
  stationary_speed_mps         정지 속도 문턱
  current_limit_a              추가 소프트웨어 전류 감시값

calibration_verified와 hardware_timeout_verified는 확인 결과를 기록하는 입력입니다.
true라는 설정 자체가 보정이나 펌웨어 조회를 수행하는 것은 아닙니다.
VESC의 실제 통신 timeout과 0A 구동 해제 동작을 확인한 뒤 기록해야 합니다.
공유 기록의 300ms timeout은 과거 확인값이며 현재 펌웨어를 재조회해야 합니다.
전류 제한은 실제 펌웨어에 적용돼 있어야 합니다. 이 노드는 펌웨어를 수정하지 않습니다.

기존 teleop.yaml은 speed_min=max=0인 수동 듀티 프로필입니다.
ERPM 시험에는 드라이버의 실제 speed_min/max, servo_min/max와 current=0 허용을
확인해야 합니다. 이 노드의 YAML을 바꿔도 드라이버 제한은 바뀌지 않습니다.

처음에는 차량을 고정하고 바퀴를 지면에서 띄워 방향·정지를 확인하세요.
확인된 정지 수단을 준비하고 수동/Python/다른 자율 명령 발행자는 종료합니다.

7. 시간 제한 시험 시작과 정지

확인한 설정 파일을 사용해 bench 모드로 실행합니다.
ros2 run nomad_control_cpp controller_node --ros-args \
  --params-file /home/user/nomad_cpp_ws/src/nomad_control_cpp/config/controller.yaml \
  -p mode:=bench

실행만으로 움직이지 않습니다. 다음 조건이 모두 필요합니다.
  calibration_verified=true, hardware_timeout_verified=true
  fault 없는 최신 telemetry와 연속 정지 상태
  명령을 받을 드라이버 subscriber 연결
  telemetry publisher 1개
  speed/current/servo의 publisher가 이 노드 1개씩뿐임
  duty/brake/position publisher는 없음

다음 서비스는 실제 설정된 시험을 시작하므로 준비가 된 상태에서 호출합니다.
ros2 service call /nomad_vesc_trial/start_test std_srvs/srv/Trigger "{}"

즉시 시험 중단:
ros2 service call /nomad_vesc_trial/stop std_srvs/srv/Trigger "{}"

재시험은 최신 정지 상태에서 명시적으로 reset 후 start_test를 호출합니다.
ros2 service call /nomad_vesc_trial/reset std_srvs/srv/Trigger "{}"

stop은 이 노드가 시작한 시험만 중단합니다. monitor의 stop이나 시험 시작 전 stop으로
다른 제어기의 차량을 정지시킬 수 있다고 생각하면 안 됩니다.

8. 동작과 한계

제어 주기: wall 20Hz. 시간 제한은 steady clock으로 계산합니다.
조향 명령은 중립에서 목표로 변화율 제한을 적용하고, 목표 명령 도달 후 설정한 시간을
기다린 다음 모터 목표를 증가시킵니다. 이것은 실제 조향 센서의 도달 확인이 아닙니다.
시험 시간이 짧으면 조향 준비만 하다가 끝날 수 있으며, 시간을 자동 연장하지 않습니다.
5초는 설정 가능한 시간의 상한입니다. 소프트웨어 중단은 다음 타이머 실행에서 처리되므로
주기·스케줄링 지연이 있으며, 실제 물리적 정지까지의 시간은 별도로 측정해야 합니다.

정지 요청/시간 만료/telemetry 이상/과전류/fault/타이머 지연/다른 발행자 발견 시
이동 명령을 중단하고 정지 출력을 보냅니다: stop_brake_current_a·stop_handbrake_current_a가 0이면
commands/motor/current에 0A, 설정하면 |ERPM|>stop_handbrake_below_erpm에서 commands/motor/brake,
그 이하에서 commands/motor/handbrake(패치한 VESC 드라이버 필요)를 보냅니다.
STOPPED_OUTPUT은 출력 중단 상태이지 차량의 물리적 정지를 뜻하지 않습니다.
0A는 관성 정지입니다. 브레이크 전류는 감속만 하고, 핸드브레이크는 정지 유지지만 미끄러져도 ERPM이 0으로 보입니다.
핸드브레이크는 다음 구동 명령까지 유지하고(실제로 안 잡히면 브레이크로 돌아감), VESC 고장 코드로 잠기면 브레이크·핸드브레이크 없이 0A입니다.
정지 때 서보를 갑자기 중앙으로 돌리지 않습니다.

한 번 시험을 시작한 뒤에는 정지 상태에서도 정지 출력을 계속 보냅니다.
다른 제어기로 넘기려면 실제 정지 확인 후 이 노드를 종료하세요.
정상 Ctrl+C/SIGTERM 종료 때에도 제한된 횟수로 정지 출력을 보냅니다. 그 뒤 VESC는 300ms timeout 후 풀립니다.
SIGKILL, 프로세스 정지, 전원 상실에는 종료 코드를 실행할 수 없으므로 실제 VESC timeout이 필수입니다.

ROS graph 검사는 경쟁 발행자를 발견하는 보조 검사이지 원자적 잠금이 아닙니다.
DDS 발견 지연 중의 다른 publisher나 ROS 밖의 직접 USB 제어까지 차단하지 않습니다.
고정 목표 start_test는 서비스 연결이 끊겨도 최대 설정 시간까지 진행될 수 있습니다.
수동 GUI 세션에는 별도로 갱신 만료 감시(기본 0.35초)가 있습니다.
상시 deadman 입력이나 독립 하드웨어 비상정지를 대신하는 기능은 아닙니다.

이 노드는 VehicleState/Planning READY를 발행하지 않습니다.
실차 조향 측정이 없는데 valid=true로 표시하거나 LPP를 준비 상태로 속이지 않습니다.
실제 목표 추종 자율주행은 별도의 DriveCommand 계약·제어권 전환을 구현한 뒤 연결해야 합니다.
