NOMAD C++ 속도·조향 변환 — 읽기, 보정값 입력, 테스트 안내

1. 이 프로젝트가 하는 일

이 코드는 C++17로 목표 속도(m/s)와 NOMAD 등가 조향각(rad)을
모터 raw ERPM과 정규화 서보값으로 계산합니다. VESC raw ERPM 측정을
m/s로 환산하는 함수도 제공합니다.

이 안내의 nomad_convert는 ROS, USB, 모터 또는 서보에 연결하지 않습니다.
추가된 controller_node는 별도 ROS 2 telemetry/시험 노드입니다.
ROS 빌드·비구동 확인·시간 제한 시험은 ROS_TRIAL_GUIDE.ko.txt를 참고하세요.
계산이 성공했다는 사실은 실제 차량의 속도·조향이 정확하다는 뜻이 아닙니다.

  데이터 구조와 함수 이름입니다. 먼저 각 필드의 단위를 읽으세요.

  라이브러리, 예제 실행 파일, 테스트를 빌드하는 규칙입니다.

3. 보정값을 넣는 위치

config/calibration.hpp의 kCalibration에 넣습니다. 각 숫자 옆의 주석이
Calibration 구조체 필드와 같은 순서입니다. 숫자 순서를 바꾸거나 생략하지 마세요.
현재 값은 전부 가상 예시이며 측정값이 아닙니다.

speed_gain
  같은 시간 구간의 실제 속도 v=D/T와 새 전방 기준 평균 ERPM e로
  e=K*v+b를 맞춘 기울기 K입니다. 단위는 ERPM/(m/s), 양수로 관리합니다.
speed_offset
  위 회귀식의 b입니다. 저속에서 안 도는 현상을 큰 offset으로 덮지 않습니다.
steering_gain
  앞축 중심 선회 반경으로 구한 등가각 alpha와 서보 명령 u를
  u=K*alpha+b로 맞춘 기울기입니다. 부호에 후륜 조향 방향이 포함됩니다.
steering_offset
  등가각 0, 즉 직진할 때의 서보 중립값입니다.
command_erpm_sign
  정규화 ERPM을 실제 VESC 명령 방향으로 바꾸는 +1 또는 -1입니다.
feedback_erpm_sign
  raw telemetry를 새 전방 기준 ERPM으로 바꾸는 +1 또는 -1입니다.
  명령 부호와 독립적으로 확인해야 합니다.
speed_min_mps / speed_max_mps
  명령으로 사용할 수 있도록 보정·검증한 속도 범위입니다.
  현재 예시의 0~0.40m/s는 실제 최소 안정 속도 검증이 아닙니다.
  실제 센서리스 저속 불안정 구간이 있으면 이후 제어기에서 따로 거부해야 합니다.
steering_min_rad / steering_max_rad
  보정·검증한 등가각 범위입니다. 서보각이나 도(degree)가 아닙니다.
servo_min / servo_max
  실제 측정으로 확인한 서보 사용 범위입니다. 장치의 0~1 범위와 구분합니다.
motor_erpm_min / motor_erpm_max
  계산 결과에 적용할 raw ERPM 명령 범위입니다. 실제 드라이버 설정과
  일치시켜야 하며, 여기의 값을 바꿔도 VESC 펌웨어는 바뀌지 않습니다.

kMeasuredOnVehicle=false와 kCalibrationNote는 보정 출처 표시입니다.
측정과 별도 검증이 끝난 뒤 실제 조건·날짜·데이터 경로를 기록하세요.
true로 바꿔도 실차가 검증되거나 구동이 허가되는 기능은 없습니다.
이 프로그램은 그 값과 무관하게 언제나 오프라인 계산만 합니다.

이번 버전은 C++ 헤더에 보정값을 넣으므로 수정 후 재빌드해야 합니다.
YAML을 읽는 기능은 없습니다. 나중에 ROS 파라미터를 붙일 때도
Calibration 구조체와 validateCalibration()을 그대로 재사용할 수 있습니다.

4. Windows에서 빌드하고 실행하기

PowerShell:

Set-Location 'C:\Users\user\Documents\ChatGPT\NOMAD\nomad_control_cpp'
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
.\build\nomad_convert.exe 0.30 0.15 -1740

현재 PC에서는 MSYS2 UCRT64의 GCC, CMake, Ninja를 사용해 빌드했습니다.
새 터미널에서 명령을 못 찾으면 C:\msys64\ucrt64\bin이 PATH에 있는지 확인하세요.

보정값 수정 후에는 다음 두 명령으로 다시 빌드·검사합니다.

cmake --build build
ctest --test-dir build --output-on-failure

프로그램 인자는 목표속도[m/s], 목표등가각[rad], raw telemetry[ERPM] 순서입니다.
인자를 생략하면 0.30, 0.15, -1740이라는 가상 입력을 사용합니다.
세 번째 값은 실시간 측정이 아니라 사용자가 전달한 숫자입니다.

5. Raspberry Pi에서 빌드하기

프로젝트 폴더를 Pi의 개발 경로로 복사한 뒤, 그 폴더에서 실행합니다.
Windows build 폴더는 복사하지 않습니다. Pi에서 새로 빌드해야 합니다.
C++17 지원 컴파일러와 CMake, Make 또는 Ninja가 설치돼 있어야 합니다.

cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
./build/nomad_convert 0.30 0.15 -1740

Pi에서의 실제 빌드·실행은 이번 작업에서 수행하지 않았습니다.

6. 현재 가상 보정값으로 나와야 하는 결과

입력: 목표 0.30m/s, 등가각 +0.15rad, raw telemetry -1740ERPM

motor_erpm=1800.000000 servo_position=0.430000
feedback_speed_mps=0.290000

계산:
  e = 6000 * 0.30 + 0 = 1800
  raw 명령 = (+1) * 1800 = 1800
  u = (-0.60) * 0.15 + 0.52 = 0.43
  측정 v = ((-1) * (-1740) - 0) / 6000 = 0.29

추가 수동 검사:
  .\build\nomad_convert.exe 0 0 0
    → 0 ERPM, 서보 중립 0.52, 환산속도 0
  .\build\nomad_convert.exe 0.5 0
    → 속도 보정 범위 초과 오류, 종료코드 1
  .\build\nomad_convert.exe 0.3 0.25
    → 조향 보정 범위 초과 오류, 종료코드 1
  .\build\nomad_convert.exe -0.1 0
    → 현재 예시는 후진 보정이 없으므로 오류
  .\build\nomad_convert.exe nan 0
    → NaN 입력 오류
  .\build\nomad_convert.exe 0.3 0 -3600
    → 측정은 +0.60m/s로 표시: 실제 초과 속도를 0.40으로 숨기지 않음

7. 자동 테스트의 의미

ROS를 끈 오프라인 빌드의 ctest는 다섯 가지 시험을 실행합니다.
  mapping_contract: 변환 라이브러리의 704개 조건 검사
  trial_state_machine: 시간 제한·상태·정지 판단의 90개 조건 검사
  cli_zero: 실제 설정을 읽은 실행 파일의 정지·중립 계산
  cli_reject_nonfinite: NaN 입력에 실패 종료하는지 확인
  cli_reject_text: 0.3oops 같은 잘못된 숫자 입력 거부

변환 라이브러리 시험에는 기준값, 좌우 끝점, 미보정 후진 거부,
입력·설정 NaN, 부호 오류, 서보·ERPM 범위 초과, 영점 예외 처리,
명령·측정 부호 4개 조합의 전후진 왕복 변환, 계산 overflow가 포함됩니다.
test_mapping.cpp의 fixture()는 고정된 시험용 데이터입니다.
실차 보정값을 바꿀 때 시험을 통과시키려고 fixture()를 함께 바꾸지 마세요.
새 실측 결과를 검증하려면 별도 독립 검증 데이터를 추가해야 합니다.

테스트 통과는 소프트웨어 계산·검사 동작에 대한 확인입니다.
계수의 실차 정확도, 정지 성능, 통신 단절 대응을 검증한 것은 아닙니다.

8. 함수 호출 시 결과를 사용하는 방법

const auto result = nomad::convertTarget(v, alpha, cfg);
if (!result.value) {
    // result.error로 이유를 기록하고 상위 제어기에서 정지 처리합니다.
    // 이전 이동 명령을 재사용하지 않습니다.
    return;
}
const double erpm = result.value->motor_erpm;
const double servo = result.value->servo_position;

std::optional은 값이 없을 수 있다는 뜻입니다. 검사 없이 value에 접근하지 마세요.
계산 결과를 출력할지 여부는 이후 ROS 제어기의 상태·유효기간 검사 뒤에 결정합니다.

9. 오프라인 변환 프로그램과 ROS 시험 노드의 경계

nomad_convert에는 ROS IO가 없습니다. 별도 controller_node에 telemetry 최신성,
구동 시험 허용, 고장 래치, 변화율 제한, 시간 제한과 0A 구동 해제를 추가했습니다.
DriveCommand 기반 자율주행과 VehicleState 발행은 아직 연결하지 않았습니다.

목표 속도 0이면 offset을 더하지 않고 ERPM 0을 계산합니다.
이 계산만으로 능동 제동이나 실제 정지를 보장하지 않습니다.
서보 명령에서 실제 조향 센서값을 만들어내지도 않습니다.

실측 ERPM 환산 함수는 초과 속도나 반대 방향 움직임도 반환합니다.
보정 범위 밖의 측정은 진단에는 유용하지만 환산 정확도가 보장되는 범위가
아니므로 이후 제어기가 별도 상태·정지 판단을 해야 합니다.
