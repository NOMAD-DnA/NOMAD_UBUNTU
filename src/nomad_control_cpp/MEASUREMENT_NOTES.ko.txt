  기존과 같은 임시 변환 비율0.25 servo/rad를 유지해 입력 범위를 넓혔다.

    입력 -0.4 rad → 서보0.400

    다음 후보 +0.55 rad → 서보0.6375

5. 현재 정지·감시 동작과 검증 한계
  속도 목표0은 수신 후 다음 제어 주기에서0A 해제한다.
  STOP은 세션을 종료하고0A 해제한다. 모두 coast이므로 관성 회전이 남을 수 있다.
  STOP이 서보를 자동으로 중립으로 돌리지는 않는다.
  제어50Hz, 상태10Hz, GUI UPDATE 최대20Hz.
  가속1200 ERPM/s, 양수 목표로 낮출 때 감속2400 ERPM/s.
  목표와 송신 명령이50 이상인데 abs(피드백)<50이 연속2초면 FAULT·0A.
  이 감시는 간헐적으로50을 넘는 진동을 모두 판별하지는 않는다.
  현재 공중 Wi-Fi 연속 MANUAL 후보는 발행 시각 기준 통신 만료2초를 사용한다.
  기본값과 MOTOR/STEERING 단기 시험은0.35초 이하를 유지한다.
  telemetry0.30초와 제어 지연0.20초는 모든 해당 시험에서 유지한다.

6. 수동 제어 자동 해제 원인과 추가 수정 상태
  MANUAL axis의 duration=0 연속 제어가 시작 후 약8.75초 및57.7초에 끝난
  로그의 이유는 'raw GUI command timeout'이었다. 3초 단기 시험 타이머가 아니다.
  제어기가 마지막으로 받은 GUI 갱신 이후350ms를 넘겨 정지한 것으로 확인했다.

  별도 HTTP 회귀 시험에서 기존 서버는 idle keep-alive 연결4개가 worker를
  점유하면 유효하게 인증된 STOP 요청도 제때 처리하지 못하는 문제를 재현했다.
  이는 지연을 유발할 수 있는 확인된 서버 문제다. 두 실차 만료의 각 패킷을
