## 1. 이번에 전달한 것

- **실제 ROS GPP 수정**: 기존 경로가 유효하면 검사만 수행하고 같은 경로·중간 목표를 주기적으로 재발행하지 않는다. 필요할 때 새 경로를 발행한다.
- **수신 순서 처리**: 경로를 한 번만 발행해도 목표·중간 목표·경로의 서로 다른 도착 순서 때문에 명령 선택기가 영구 정지하지 않도록 수정했다.
- **실제 Gazebo 시험 환경**: Hybrid A* + RPP + 명령 선택기 + Control + 차량 물리를 실행하는 6개 시나리오다.
- **시험 GUI**: 큐 추가·순차 실행·중지·Gazebo 화면 열기·시나리오별 결과 그래프를 제공한다.
- **시험 데이터 스냅샷**: 메인 큐 106개와 초기 검증 자료를 포함한 전체 파일을 압축 보존했다. 복원 스크립트도 포함한다.

## 2. 가장 먼저 알아둘 시험 범위

**사용자가 선택한 이번 시험은 플래닝 검증이다.** 차량은 Gazebo 물리로 움직이며 위치는 GT, 지도는 정답 격자의 관측 가능한 부분을 점차 공개한다. B0 의미분할·실제 깊이 사영·VIO/GNSS 융합을 이 시험에서 실행하거나 검증한 것은 아니다.

실험실 기본 ROS domain은 **142**, 일반 전체 실행 기본은 **42**다. `use_sim_time=true`이며 Gazebo partition도 분리한다. 같은 domain/partition의 기존 모듈이 있으면 시험을 거부한다. 이미 실행 중인 다른 작업을 임의 종료하면 안 된다.

현재 실험실 프로파일은 **전진 Hybrid A* + RPP**, 후진 복구 비활성이다. 6번의 한계는 이 구현·설정에 대한 것이며 Hybrid A*라는 알고리즘 계열 전체가 후진을 못 한다는 뜻이 아니다.

## 4. 전달한 106개 기록을 보는 방법

저장소에는 `sessions/`의 실시간 파일 대신 `datasets/planning_lab/20261027/planning_lab.tar.xz`와 파일별 SHA256 manifest를 넣었다. 저장소 루트에서:

```bash
python3 scripts/restore_scenario_lab.py --verify-only
python3 scripts/restore_scenario_lab.py
./scripts/run_scenario_lab.sh --root sessions/planning_lab_archives/20261027
```

기본 복원 위치는 새 폴더 `sessions/planning_lab_archives/20261027`이다. 이미 존재하면 덮어쓰지 않는다. 추가 복원이 필요하면 `--output 새폴더`를 지정하고 GUI에도 같은 `--root`를 준다. 데이터 검증·압축 해제 자체는 Python 표준 라이브러리만 사용한다.

복원 스크립트가 큐의 실행 폴더 링크를 새 PC의 위치로 바꾼다. 과거 로그·manifest·SDF의 절대 경로는 당시 출처 증거로 남긴다. 새 주행은 현재 맵 생성기로 새 실행 폴더에 만들어 시작한다. `pids.json`·`ownership.json`의 과거 PID를 현재 프로세스 종료에 사용하지 않는다.

### 개수를 혼동하지 말 것

| 범위 | 개수 | 의미 |
|---|---:|---|
| 메인 `queue.json` | **106** | 사용자가 전달을 요청한 큐 시험 기록 |
| 메인 `runs/*/outcome.json` | **113** | 위 큐 외 초기 CLI 검증도 포함 |
| 스냅샷 전체 `outcome.json` | **116** | 초기 개발/중지 검증까지 포함 |
| 스냅샷 전체 파일 | **3,700** | 맵·설정·원시 표본·로그·집계 등 |

106개 큐의 상태는 `arrived` 58, `safe_stop` 16, `forward_limit` 17, `envelope_overlap` 8, `stalled` 7이다. **106개가 모두 성공한 것은 아니다.**
전체 `outcome.json`을 재귀 검색한 116개를 곧바로 “106회 반복 시험”의 분모로 사용하면 안 된다. 그 분석은 메인 `queue.json`의 실행 ID/폴더와 결과를 연결해서 한다. `verification_summary.json`은 초기 6개 검증의 요약이며 이후 누적 시험을 대표하지 않는다.

## 5. 시나리오와 성공 판정

| 번호 | 시나리오 | 기대 결과 |
|---|---|---|
| 1 | 넓은 직선 통로의 기본 추종 | 목표 도착 |
| 2 | 넓은 길의 단일 장애물 | 우회 후 목표 도착 |
| 3 | 짧은 고비용 경사 구간과 완만한 우회 공간 | 비용을 반영한 주행 후 도착 |
| 4 | 연속 S자 통로 | 연속 조향 후 도착 |
| 5 | 진행하다 발견하는 막다른길 | 벽 앞 정지, 목표 미도달 |
| 6 | 후진해야 탈출할 수 있는 포켓 | 전진 경로 부재로 정지, 목표 미도달 |

5·6번은 `completed=false`와 `expected_result_met=true`가 동시에 나올 수 있다. 완주율과 시나리오 기대 결과 충족률을 분리해서 보고해야 한다. `forward_limit` 판정은 실행기의 판정 조건에 따른 시험 결과이며, 모든 가능한 경로를 수학적으로 부정했다는 뜻은 아니다.

HTML의 XY 격자·비용·출발·목표를 보존했지만, HTML에 높이는 없어서 3번에 최대 0.30m 곡면을 추가했다. **합성 비용은 그 곡면의 실제 경사에서 산출한 값이 아니다.**
지도는 반경 7.5m 방사형 LOS 관측이며 카메라의 실제 화각·관측 증거·감쇠 모델을 재현하지 않는다. 6번에는 뒤쪽 출구를 본 과거 위치의 정답 관측을 제공한다. 상세 차이는 실험실 안내와 `core.py`, `worlds.py`, `config.yaml`에서 확인한다.

## 6. GPP 변경을 분석할 때의 핵심

적용 범위는 **`observed_corridor` + `corridor.retain_safe_path=true`**다. `direct` 모드나 옵션이 꺼진 경우까지 동일하다고 일반화하지 않는다.

- 정상 유지: `/nomad/corridor_status`의 `state=validated_safe_path`, `publication=none`. GPP 경로 발행 횟수는 증가하지 않는다.
- 경유점 도달·최종 목표 전환·유지 조건 이탈 등: 필요한 새 경로를 발행한다. 동일 좌표의 중간 목표는 반복 발행하지 않는다.
- 빈 경로로 무효화한 뒤: 유효한 참조가 다시 발행돼야 추종을 재개한다.
- 기존 유지 조건에는 경로와 차량의 위치 차이 25cm, 방향 차이 15도 등의 검사가 있다. “새 장애물이 없는데 재계획했다”만으로 불필요한 재발행이라고 단정하지 않는다.
- 전역 경로는 캐시하고, 지역 주행 명령·지도·위치·제어 피드백의 freshness 검사는 유지한다. 명령 선택기의 mission 경계는 timestamp가 있는 목표의 발행 시각이다.

`events.jsonl`의 `validation_reason`, `previous_path_invalidated`, `publication`, `replanned_after_invalidity`와 파트 로그를 함께 본다. 옛 시험에 필드가 없으면 해당 지표를 추정해 확정값으로 쓰지 않는다.

## 8. 지표와 검증을 해석할 때

- **장애물 여유 p05**는 약 10Hz 표본의 차량 사각 외곽과 GT 장애물 간 XY 거리다. 0은 보수적 외곽 겹침이며 접촉력 센서로 측정한 충돌과 구분한다.
- **CPU**는 각 GPP/LPP 프로세스의 user+system 누적 차이인 core·s다. CPU 비율이나 한 번의 알고리즘 계산 시간으로 읽으면 안 된다.
- **시간**은 sim 시간과 wall 시간을 구분한다. 목표 도착은 위치 0.35m 이내·저속 정지 조건이며 목표 yaw 만족을 검증하지 않는다.
- **GPP 발행 수**는 비어 있지 않은 경로 수다. 무효 후 재계획은 무효 판정 뒤 실제 새 경로가 나온 수이며 실패한 탐색 횟수와 다르다.
- 실행별 설정과 `manifest.json`의 소스 해시를 비교한다. 초기 개발·수정·재검증이 포함돼 있으므로 모든 기록이 같은 코드·설정으로 수행됐다고 가정하지 않는다. 해시가 없는 옛 기록은 확인 불가로 구분한다.

전달 시점에 planning/bringup 회귀 **319개 통과**, 실제 Gazebo 6개 시나리오 실행, GUI 큐 전환·중지, 데이터 체크섬·106개 큐 링크 복원을 확인했다. 초기 각 시나리오의 기대 결과 충족과 이후 반복 시험의 실패는 별개이며, 실제 인지/위치추정 통합·실차 검증 완료를 뜻하지 않는다.
