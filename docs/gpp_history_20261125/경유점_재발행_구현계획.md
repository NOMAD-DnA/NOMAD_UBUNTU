# 경유점 재발행(주기적 재선택) 구현 계획

기준 코드: Jetson `~/nomad_planning_ws/src` (2026-11-24 수정본, Pi4 원본의 복사본)
수정은 README_FIRST 규칙대로 **Pi4 원본에서 하고 Jetson으로 다시 복사**한다.

## 0. 원칙 — 인터페이스는 그대로

- ROS 토픽·메시지·서비스·QoS, 발행 필드, 상태(reason) 문자열 형식: **변경 없음**
- 기존 공개 함수 시그니처(`Navigator::step`, `CorridorSelector::candidates/retained_path/accept/reject` 등): **변경 없음**
- `NavigationOutput` 구조: **변경 없음**
- 추가되는 것은 (1) 설정 구조체의 기본값 있는 필드, (2) 클래스 내부(private) 상태·헬퍼, (3) 선택적 ROS 파라미터뿐
- 새 기능은 **기본 꺼짐**(`corridor.reissue_enabled=false`). 꺼져 있으면 기존과 동일하게 동작해야 하며 회귀 시험으로 확인한다.

## 1. 현재 동작 (왜 재발행이 안 되는가)

`policy.cpp` `Navigator::step`
- 549행 `due = now - last_plan_ >= replan_period(1 s)`
- 553행 경로가 안전하면 `retained_path()`로 기존 경유점·경로를 그대로 사용 (`retain_safe_path=true`, ROS 파라미터로 노출 안 됨)
- 556행 `candidates()`를 불러도, 348행 `active_transit_path_revalidated` 조기 반환으로 **기존 경유점을 그대로 돌려줌**
→ 이상이 없으면 경유점 도착 전까지 같은 경유점 유지.

## 2. 설정 추가 (`policy.hpp` `CorridorConfig`, 기본값 포함)

경유점이 1~2 m 사이(반경 설정 1.25~2.0 m, 막히면 더 가까이)에서 바뀌므로 **고정 거리 대신 채택 당시 경로 길이 L0에 대한 비율**로 정한다.

| 필드 | 기본값 | 의미 |
|---|---|---|
| `reissue_enabled` | false | 재발행 기능 켜기 |
| `reissue_travel_ratio` | 0.4 | 마지막 계획 이후 이동 거리 ≥ 0.4·L0 이면 재발행 |
| `reissue_min_travel` | 0.2 m | 이동 거리 하한(너무 잦은 재발행 방지) |
| `reissue_end_margin` | 0.6 m | 남은 경로 ≤ 0.6 m 이면 재발행(RPP 끝 감속 구간 0.5 m 진입 전) |
| `reissue_margin` | 0.15 | 새 후보 점수가 기존보다 이만큼 낮아야 교체(히스테리시스) |
| `reissue_min_interval` | 1.0 s | 재발행 최소 간격(LiDAR 1 Hz) |

예시 (L0 = 채택한 경로 길이)

| L0 | 이동 조건 max(0.2, 0.4·L0) | 남은 경로 조건 |
|---|---|---|
| 1.0 m | 0.4 m 이동 | 0.6 m 이하 |
| 1.5 m | 0.6 m 이동 | 0.6 m 이하 |
| 2.0 m | 0.8 m 이동 | 0.6 m 이하 |

고정값(0.5 m 이동·1.0 m 남음)을 쓰면 L0 = 1.0 m일 때 채택 직후부터 "남은 경로 1.0 m 미만"이 성립해 매 지도마다 재발행하는 문제가 생긴다.

`Navigator` 생성자 검증(459행 근처)에 유한값·양수 검사 추가.

## 3. 내부 상태 추가 (`policy.hpp` `Navigator` private)

- `Pose plan_pose_` — 새 경로를 채택했을 때 차량 위치
- `double plan_length_=0` — 채택한 경로 길이 L0 (`path_length(reference_)`)
- `std::size_t progress_index_=0` — 경로 위 진행 위치(앞쪽으로만 증가)
- `std::int64_t plan_map_stamp_=0` — 그때 사용한 전역 지도 시각(`layers.grid.stamp_ns`)
- `double last_reissue_=-kInf` — 마지막 재발행 판단 시각

604행(경로 채택) 직후 위 세 값을 갱신한다.

## 4. 재발행 조건 (`Navigator::step`, 551~553행 사이)

다음을 **모두** 만족하면 `reissue=true`:
1. `reissue_enabled` 이고 `target_`·`reference_`가 있음
2. 기존 경로가 안전함(`previous_route_clear`) — 위험하면 기존 재계획 경로가 이미 처리
3. `!retry_ && !isfinite(failed_since_) && !probe`
4. **새 지도 도착**: `layers.grid.stamp_ns != plan_map_stamp_` (LiDAR 1 Hz 갱신 전에는 다시 골라도 결과가 같음)
5. `now - last_reissue_ >= reissue_min_interval`
6. 진행 거리 `s >= max(reissue_min_travel, reissue_travel_ratio·plan_length_)` **또는** 남은 경로 `plan_length_ - s <= reissue_end_margin`
   - `s` = **채택한 Hybrid A* 경로(`reference_`) 위에서 잰 진행 거리**: 경로 시작점부터 현재 위치를 경로에 수직으로 내린 점까지의 누적 길이
   - 직선거리나 오도메트리 누적 주행거리가 아님(옆으로 비켜 가거나 S자 경로에서도 "경로를 얼마나 소화했는지"를 일관되게 봄)
   - 가장 가까운 점이 S자·되돌아오는 구간에서 튀지 않도록, 직전 인덱스부터 **앞쪽으로만** 찾는다(`progress_index_`, 경로 채택 시 0으로 초기화)
   - 차가 경로에서 0.25 m 넘게 벗어나면 기존 `retained_path` 규칙상 이미 재계획되므로 별도 처리 불필요
7. 현재 목표가 최종 목표로 잠긴 상태(final goal lock)가 아님

`reissue=true`이면 553행의 `retained_path()`를 건너뛴다.

## 5. 새 후보 계산 (`CorridorSelector`)

- 새 공개 메서드 1개 추가(기존 메서드는 그대로):
  `std::vector<CorridorCandidate> reissue_candidates(const CostField&, const Pose& start, const Pose& goal, double now, double* active_score);`
- 내부에서 private 플래그를 세워 기존 `candidates()` 본문을 그대로 쓰되, **348행 기존 경유점 조기 반환만 건너뛴다**.
- 계산된 후보 목록에서 기존 경유점(`active_`)과 `separation` 안에 있는 후보의 점수를 `*active_score`로 돌려준다. 기존 경유점이 목록에 없으면(뒤로 넘어감, 너무 가까움 등) 무한대.
- 점수 계산식·후보 자격·정렬·최대 16개 규칙은 변경 없음.

## 6. 교체 판단과 경로 생성 (`Navigator::step`)

1. `choices = reissue_candidates(...)`
2. 히스테리시스: `c.final || c.score + reissue_margin < active_score` 인 후보만 남김
3. 남은 후보가 없으면 → **기존 경유점·경로 유지**, `last_reissue_=now`, `plan_map_stamp_=현재 지도 시각`(같은 지도로 반복 시도 방지)
4. 있으면 → 기존 후보 시도 루프(561~594행)를 그대로 사용. 이 부분은 private 헬퍼(`try_candidates`)로 분리해 일반 재계획과 공유한다(동작 변경 없음).
   - 시간 예산: 기존 규칙대로 `previous_route_clear`이면 0.15 s
   - 성공 → 새 경로 채택(604행과 동일 처리), 3절 상태 갱신
   - 실패 → **기존 경로 유지**(597행 `previous_route_clear` 분기와 동일). 기존 경유점은 reject하지 않음. 실패한 새 후보만 기존 규칙대로 3초 제외.

## 8. 시험

1. **동일성**: `reissue_enabled=false`에서 `policy_parity_cli`, `corner_scenarios`, `test_corner_regressions`, `test_policy`, `test_rpp_rejections` 결과가 수정 전과 같음
2. **단위 시험(test_policy.cpp 추가)**
   - 경로 길이 1.0 / 1.5 / 2.0 m 각각에서 이동 조건 전에는 재발행 없음, 조건 뒤에는 재발행
   - 짧은 경로(L0 ≤ 0.6 m)에서 매 지도마다 재발행하지 않음(min_interval·min_travel)
   - 같은 지도 시각이면 재발행 없음
   - 점수 개선 < margin이면 기존 경유점 유지
   - ㅏ자 격자에서 갈림길이 새로 보이면 교체
   - 새 후보 탐색 실패 시 기존 경로 유지, 기존 경유점 미제외
   - 최종 목표 잠금 상태에서는 재발행 없음
3. **SILS(Gazebo)**: ㄱ자(시나리오 7), ㅏ자 맵에서 켬/끔 비교 — 도착 시간, 정지 횟수, 경유점 교체 횟수, 조향 흔들림(조향각 변화량)
4. **실차**: Jetson 시험 사본에 파라미터만 켜서 비교
