# Pi 4 VESC 30A 실차 시험 변경 (2026-10-30)

## 이번에 실제 확인한 것

- Pi 4 `lpp`에서 VESC USB가 `/dev/serial/by-id/usb-STMicroelectronics_ChibiOS_RT_Virtual_COM_Port_304-if00`으로 잡혔다. 펌웨어는 5.03, 하드웨어 응답은 `75_300_R2`였다.
- 변경 전 펌웨어 설정은 **모터 전류 +50/−50A, 배터리 입력 최대 50A, 명령 타임아웃 500ms**였다. 기존 값은 `/home/user/vesc_ws/backups/20261030_171927/`에 백업했다.
- 기존 `vesc_ws/inspect_vesc.py --bench-current-a 30 --set-timeout-ms 300`으로 설정을 기록했다. 기록 직후와 별도 재접속에서 **모터 +30/−30A, 배터리 입력 최대 30A, 회생 0A, 타임아웃 300ms**를 읽어 확인했다.
- Pi 4의 `/home/user/nomad_link_ws`에 Control/Planning 소스와 실행 스크립트를 배포하고 두 패키지 빌드를 완료했다. Control 비구동 4초 실행, VESC 드라이버 연결·telemetry 수신, 실행 전 펌웨어 설정 검증도 통과했다.
- 사용자가 바퀴를 들어 올린 상태를 확인한 후 새 `nomad_control/vesc_controller`가 `/nomad/planning/drive_command`의 **0.4m/s 목표를 2초간** VESC ERPM 명령으로 전환했다. 출력 명령은 +1845.6 ERPM, telemetry 최고치는 약 2177 ERPM, 모터 전류 14.00A, 배터리 입력 전류 0.63A였다. Control 상태에 `RUNNING`이 기록됐고 사용자는 바퀴가 **차의 새 전방 기준 전진**했다고 확인했다. 정지 명령 후 프로세스가 종료됐고, 펌웨어 30A 설정을 다시 확인했다.
- 앞서 0.1m/s 상당 ERPM 목표 시험은 최고 약 5 ERPM에 그쳐 회전 확인으로 집계하지 않는다. 저속 센서리스 구동 특성 또는 설정 문제일 수 있어 원인은 추가 확인이 필요하다.

## 코드·운용 변경

- 기존 `max_speed: 0.0`은 새 자율제어가 미보정 상태에서 구동되지 않게 하는 **임시 잠금값**이었다. 오전의 직접 듀티 시험은 이 Control 경로를 우회했으므로 바퀴가 돌 수 있었다. 이번에는 Control의 독립 속도 상한을 제거했다. 명령의 유한값, 유효기간, 좌표계, 조향각 범위 검사는 유지한다.
- `current_limit_a: 30.0`을 추가했다. VESC telemetry에서 모터 전류 또는 입력 전류가 30A를 넘거나 유효하지 않으면 Control은 정지를 래치한다. 이는 telemetry 이후의 추가 정지 장치이며 **진짜 전류 상한은 위 펌웨어 설정**이다. ROS `vesc_driver`의 `current_max`는 전류 명령 토픽만 제한하고 ERPM 명령 중 모터 전류를 제한하지 않는다.
- `scripts/run_pi4_vesc_cycle.sh`는 VESC의 실제 모터·입력 전류 설정과 타임아웃을 다시 읽어 확인한 뒤 드라이버와 Control을 켠다. `NOMAD_ENABLE_ACTUATION=1`과 `ROS_DOMAIN_ID`가 명시돼야 실행된다. 종료 시 자신이 시작한 두 프로세스만 정리한다.
- `trial_candidate_conversion=true`는 예제에서 가져온 ERPM/조향 변환값을 이번 실차 시험에 한해 사용하는 명시적 옵션이다. `calibration_valid=false`는 그대로라 실측 보정 완료라고 표시하지 않는다.
- 조향 관절 측정값은 없으므로 `VehicleState.steering_valid=false`를 유지한다. Planning의 `allow_unmeasured_steering_trial=true`는 실차 통합 시험에서만 선택하는 임시 예외이며 기본값은 false다.
- Planning의 목표 속도 설정은 별도다. 현재 공통 차량 설정의 `max_speed: 0.5`는 Planning의 목표 생성 한도이며 이번 Control의 옛 `0.0` 잠금과 다르다. **30A 전류 제한만으로 차량 속도를 제한할 수는 없다.**

## 다음 연결

1. Jetson 통합 담당은 실차 Planning 실행에서 `allow_unmeasured_steering_trial=true`를 명시하고, 실제 localization·perception·경로·목표를 같은 ROS domain으로 연결한다. 이 옵션을 적용해도 조향이 측정됐다고 간주하면 안 된다.
2. 실제 목표점 한 사이클은 Jetson 통합이 실행된 뒤, 차량 주변 확보·바퀴 든 상태의 조향 방향 확인·지상 시험 순서로 검증한다. **이번 검증은 Pi 4의 Planning 명령 입력→Control→VESC→바퀴 회전까지이며, 목적지→지도→경로→주행 완료 시험은 아니다.**
3. Pi 4 실행 예: `cd /home/user/nomad_link_ws && ROS_DOMAIN_ID=<통합번호> NOMAD_ENABLE_ACTUATION=1 ./scripts/run_pi4_vesc_cycle.sh`. 실제 명령이 올 수 있으므로 감독자가 차와 정지 수단을 준비한 상태에서만 실행한다.

이번 변경은 기존 `/home/user/vesc_ws` 소스와 수동 `teleop.yaml`을 수정하지 않았다. VESC 펌웨어 설정은 위와 같이 영구 변경했으며 이전 페이로드가 백업돼 있다.
