# NOMAD 실차 PC GUI 연결 계약 (2026-10-30)

## 현재 완료 상태

- PC용 ROS 2 패키지 `src/nomad_operator_gui` 생성, PC Jazzy에서 빌드 성공.
- 실행 스크립트 `scripts/run_real_operator_gui.sh` 생성.
- GUI에 OAK 전방 영상, 전역 주행 그리드맵, 지도 클릭으로 목적지 선택, 별도 목표 전송 버튼 구현.
- 지도 클릭 XY 변환 단위시험 2개 통과, 화면 시작 시험 통과, 시험용 ROS 토픽에서 목표 좌표 발행·수신 확인.
- Jetson 통합 시스템은 아직 실행 전이다. 따라서 Jetson 영상·맵 실수신과 실제 플래너 목표 수락은 아직 검증하지 않았다.

## Jetson 담당자에게 필요한 토픽

| 발행 주체 | 토픽 | ROS 2 타입 | 프레임/형식 | GUI 쪽 QoS |
|---|---|---|---|---|
| OAK/Jetson | `/oak/rgb/image_raw` | `sensor_msgs/msg/Image` | 전방 RGB, `rgb8` 또는 `bgr8` 권장 (`mono8`도 지원) | best effort, volatile, depth 5 |
| 지도/Jetson | `/nomad/navigation_costmap` | `nav_msgs/msg/OccupancyGrid` | `header.frame_id=odom`, `info.origin` 회전 없음, `resolution`은 m/cell, data는 ROS 표준 row-major | reliable, transient local, depth 1 |
| 위치추정/Jetson (선택) | `/nomad/localization/odometry` | `nav_msgs/msg/Odometry` | `header.frame_id=odom`; GUI 차량 위치 표시용 | reliable, volatile, depth 10 |
| PC GUI | `/goal_pose` | `geometry_msgs/msg/PoseStamped` | `header.frame_id=odom`, 선택한 셀 중심의 x/y (m), `pose.orientation.w=1` | reliable, volatile, depth 10 |

현재 저장소의 기준 토픽 파일은 `src/nomad_bringup/config/topics.yaml`이다. Jetson 쪽 토픽이 다르면 GUI 실행 옵션 `--image`, `--grid`, `--odom`, `--goal`로 맞출 수 있다.

**지도 의미:** `data=-1`은 미관측, `0..100`은 비용/점유값이다. GUI는 `-1`과 `80` 이상 셀을 목적지로 선택하지 않는다. 지도 origin 위치와 해상도가 정확해야 클릭 지점의 실제 `odom` XY가 맞는다. 회전된 지도 origin은 현재 GUI가 거부한다.

**목표 흐름:** PC 사용자가 지도를 클릭해 목적지를 고른 뒤 `선택한 목적지 보내기`를 누르면 `/goal_pose`를 1회 발행한다. 목표 구독 노드가 연결되지 않으면 버튼은 비활성이다. 저장소의 PlanningInputs가 `/goal_pose`를 구독해 `/nomad/goal`로 전달한다. GUI의 “발행” 문구는 토픽을 보냈다는 뜻이며, 계획 성공·주행 시작 확인은 아니다. 실제 주행 준비 상태 및 안전 판단은 Jetson 통합 측에서 담당한다.

## 실행 순서 (PC)

1. Jetson 담당자에게 실제 `ROS_DOMAIN_ID`를 받아 PC에 같은 번호를 사용한다. 모든 장치는 상호 통신 가능한 네트워크에 있어야 한다.
2. PC Ubuntu 24.04/Jazzy에서 `python3-pyqt5`가 설치된 상태로 빌드한다.

```bash
cd /home/user/nomad_ws
source /opt/ros/jazzy/setup.bash
colcon build --base-paths src --packages-select nomad_operator_gui --symlink-install
```

3. Jetson 통합 측이 영상·맵을 발행할 때 GUI를 연다. `<번호>`를 실제 도메인 번호로 교체한다.

```bash
cd /home/user/nomad_ws
ROS_DOMAIN_ID=<번호> ./scripts/run_real_operator_gui.sh
```

4. 화면 왼쪽 영상, 오른쪽 그리드맵이 들어오는지 확인한다. 파랑 원은 차량 위치(선택 토픽 수신 시), 노랑 원은 고른 목적지다. 회색은 미관측 셀이다.
5. 차량과 Jetson 플래너의 안전 준비가 확인된 뒤 목표를 선택하고 버튼을 누른다.

## 아직 확인할 것

- Jetson 통합 실행 후 PC에서 위 3개 수신 토픽 실제 확인.
- Jetson의 영상 인코딩·지도 QoS·`odom` 프레임 계약 확인.
- `/goal_pose` 발행 후 Jetson PlanningInputs의 `/nomad/goal` 수신 확인.
- 실제 주행은 별도 차량 안전 준비를 마친 뒤 진행.

PC와 Pi 4 간 표준 ROS 메시지 양방향 통신은 이전에 시험했지만, Jetson과의 토픽 통신은 아직 시험하지 않았다.

현재 PC에는 시험용 도메인 `174`로 GUI 창을 열어 두었다. Jetson의 실제 도메인이 정해지면 창을 닫고 같은 번호로 다시 실행한다.
