# 설치 및 실행 안내

Hybrid A* + RPP의 6개 시나리오 시험은 `./scripts/run_scenario_lab.sh`로 연다.
큐·Gazebo·결과 기록 사용법은 [플래닝 시나리오 실험실](플래닝_시나리오_실험실.md)을 참고한다.

## 1. 처음 설치할 때

### 1-1. PC 환경 준비

현재 전체 시뮬레이션 기준은 **Ubuntu 24.04 + ROS 2 Jazzy + NVIDIA GPU 드라이버**.
ROS가 없다면 먼저 [ROS 2 Jazzy 공식 설치 안내](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html)를 따른다.
분할용 CUDA 라이브러리는 아래 설치 스크립트가 준비한다. Jetson용 설치는 별도 검증이 필요하다.

```bash
sudo apt update
sudo apt install git python3-venv python3-colcon-common-extensions python3-rosdep python3-pyqt5
nvidia-smi  # GPU·드라이버 확인
```

### 1-2. 프로젝트 받기

```bash
git clone --branch dev https://github.com/NOMAD-DnA/NOMAD_UBUNTU.git ~/nomad_ws
cd ~/nomad_ws
```

이미 소스를 받은 사람은 해당 폴더로 이동해서 다음 단계부터 진행한다.

### 1-3. 설치·빌드

```bash
./.nomad/install_vio.sh       # ROS/Gazebo 의존성 + Basalt·OpenVINS·융합 설치/빌드
./.nomad/install_semantic.sh  # B0 추론 환경 설치/빌드 (x86_64 CUDA)
source .nomad/env.sh
colcon build --base-paths src --symlink-install --packages-up-to nomad_bringup nomad_semantic
```

마지막 출력이 `Summary: ... packages finished`이고 실패 패키지가 없으면 실행 단계로 이동한다.
이 설치 단계는 최초 준비 때 사용한다. 평소 실행할 때마다 다시 설치하지 않는다.

## 2. 설치 후 전체 실행할 때

**터미널 1 — 전체 실행**

```bash
cd ~/nomad_ws
./scripts/run_terrain_navigation.sh viewer:=false  # 맵 → GPP/LPP 선택 → 전체 노드·RViz
```

**초기 위치추정 정렬**

함께 열린 조종 창에서 2–3m 이동하면 위치 정렬 완료 시 자동 정지하고 창이 닫힌다. 이후 지도 READY·실제 차량 정지 3초를 확인해 자율주행이 시작된다.
초기 창을 끈 경우에만 `./scripts/run_teleop.sh`로 조종하고 정지 후 창을 종료한다.

위치추정·인지가 READY이고 3초간 정지하면 자율주행이 준비된다.
RViz `2D Goal Pose`로 목표 지정. 전체 종료는 터미널 1에서 `Ctrl+C`.

## 3. 각 파트를 따로 실행할 때

전체 실행을 종료한 뒤, 아래 명령을 **각각 다른 터미널**에서 실행한다. 작업 폴더는 `~/nomad_ws`.

```bash
./scripts/run_module.sh sim           # 맵 선택·센서·차량
./scripts/run_module.sh localization  # Basalt + GNSS 융합; method:=openvins로 교체
./scripts/run_module.sh semantic      # B0 의미분할
./scripts/run_module.sh map           # 깊이·분할·융합 pose → 20cm 지도·코스트맵
./scripts/run_module.sh teleop        # 초기정렬 이동 → 정지·창 종료
```

위치추정·인지가 READY인 것을 확인한 뒤 다음을 실행한다.

```bash
./scripts/run_module.sh planning  # GPP/LPP 선택·목표 수신
./scripts/run_module.sh control   # 목표 속도·조향 → 차량
./scripts/run_module.sh rviz      # 지도·차량·경로 표시, 목표 지정
```

READY 확인이 필요하면 별도 터미널에서 `source .nomad/env.sh` 후
`ros2 topic echo /nomad/localization/status --once`, `ros2 topic echo /nomad/perception/status --once`.
각 `state: 1`이 READY다. 전체 실행과 파트별 실행을 동시에 켜지 않는다.

## 4. 수정할 파일을 찾을 때

[코드·config 위치](STRUCTURE.md). 기본 모델은 `src/nomad_semantic/models/nomad_b0_map04/`(기존 `nomad_b0/` 보존), 인지 정책은 `src/nomad_perception/config/navigation_terrain.yaml`.
현재 막다른 길 후진 복구 이력과 지도 처리 지연 문제는 미해결이다.

## DDS 영상 전달용 공유 메모리

공통 `.nomad/env.sh`를 사용하는 GUI/CLI 실행은 `.nomad/fastdds.xml`을 읽는다.
Fast DDS 공유 메모리 영역은 participant마다 16 MiB이며 UDPv4 전송도 유지한다.
기존 512 KiB보다 큰 신뢰도 영상(640×480×4 bytes)의 전달 중 손실을 줄이기 위한 설정이다.
여러 ROS 프로세스를 실행하면 공유 메모리 사용량도 늘어난다.

설정 변경에는 colcon 재빌드가 필요 없으며 실행 중인 프로세스에는 소급 적용되지 않는다.
기존 시뮬레이션과 GUI를 종료한 뒤 새로 실행한다. GUI 자식 노드에도 같은 환경이 전달된다.
사용자가 `FASTRTPS_DEFAULT_PROFILES_FILE` 또는 `FASTDDS_DEFAULT_PROFILES_FILE`을
이미 지정했다면 해당 사용자 설정을 우선한다. 다른 RMW에는 이 Fast DDS 설정이 적용되지 않는다.

```bash
source .nomad/env.sh
printf '%s\n' "$FASTRTPS_DEFAULT_PROFILES_FILE"
```

동일한 진단 실행 명령으로 `semantic_*.jsonl`의 발행 촬영 시각과 `map_*.jsonl`의
수신 촬영 시각을 비교한다. 분리 전송 시험에서 개선을 확인했으며, 실제 주행의
지도 갱신 간격과 LPP_PAUSED 감소는 적용 후 별도로 확인해야 한다.

## 미관측 초기화 변경 (2026-10-19)

현재 인지 기본값은 bootstrap_radius=0, bootstrap_override=false입니다. 센서로 확인하지 않은 출발 전방을 자동으로 통행 가능 처리하지 않습니다. 기존 실행 방식은 유지하며 실행 중인 노드에는 재시작 후 적용됩니다. 기존 GUI 저장 설정·실험 terrain_config.yaml에 양수 반경이 남아 있으면 기본값을 덮어쓸 수 있으므로 실제 `/live_terrain` 파라미터를 확인하세요. 관측 부족으로 정지하는 상황을 반경 확대로 우회하지 마세요.

## 2026-10-20 카메라 기본값

시뮬레이션 기본 카메라는 ZED 2 최대 화각의 핀홀 근사(가로110°·세로70°, 양안12cm, 리샘플링640×480)다. 실제 ZED SDK/장치 드라이버가 아니다. GUI를 재실행하면 반영된다. `/oak` 토픽명은 기존 모듈 호환성을 위해 유지한다. RGB/깊이/양안/정적TF 및 Basalt·OpenVINS 보정을 함께 변경했다. 원본 맵은 보존하고 실행용 복사본에 센서를 적용한다. 이전 프로파일은 `src/nomad_gazebo/config/sensors_oak_d_lite.yaml`이며 복구 시 VIO 보정도 함께 맞춰야 한다.

## 2026-10-20 최적화 설정을 기본 실행에 적용

`./scripts/run_gui.sh`의 기본 알고리즘은 1번 Hybrid A* + RPP다. `./scripts/run_terrain_navigation.sh`의 알고리즘 선택에서 엔터를 눌러도 1번을 선택한다. 맵 선택과 RViz 최종목표 지정 방식은 그대로다. 기존 수동 VIO 초기 정렬을 마친 뒤 주행한다.

기본 설정은 `src/nomad_perception/config/terrain_planning.yaml`이다. 관측 기반 중간 경유점과 장애물 근접·군집·미관측 비용을 사용하며, 최종목표 3m 안에 진입하면 최종목표를 유지한다. 후진복구는 비활성이다. 의미분할은 4번 맵 B0를 기본 사용한다. 다른 번호와 명시적 파라미터로 설정을 바꿀 수 있다.

이번 변경은 현재 실험 설정을 다음 실행에 적용하는 것으로, 지그재그 억제 수정이나 모든 맵의 완주 검증을 뜻하지 않는다. 실행 중인 시뮬레이션은 재시작하지 않았다. 관련 4개 패키지 빌드 성공, bringup 테스트 47개 통과, 설치된 설정·모델 경로와 GUI/CLI 기본 선택을 확인했다. 세부 값·변경 전 백업·복구 방법은 `experiments/default_profile_20261020/README.md` 참조.

## 현재 차량 구성

전체 실행과 GUI는 전륜 구동·후륜 조향이다. 공통 설정 `src/nomad_bringup/config/vehicle.yaml`, [차량 설정·단독 시험](후륜조향_시뮬레이션.md).
알고리즘 선택·맵 선택 방식은 동일하다. 새 패키지 설치 시 `colcon build --symlink-install`로 `nomad_vehicle_model`도 빌드한다.
