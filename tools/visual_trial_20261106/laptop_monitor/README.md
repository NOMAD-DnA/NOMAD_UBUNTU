# NOMAD 실물 시험 앱

실행:

```bash
bash run_app.sh
```

앱 목록 등록은 `bash install_launcher.sh` → **NOMAD 실시간 시험**.

## 운영 PC 한 대

1. **운영 · 보드 연결 / 관전 중계**를 선택한다.
2. **보드 찾기** 또는 Pi5 `user@주소`, Jetson `nvidia@주소`와 SSH 비밀번호를 입력한다.
3. **시험 시작**으로 센서·VIO·융합·인지·지도를 켠다. 이미 실행 중이면 **화면 연결 · 중계**를 누른다.
4. 실시간 창의 **운용 PC 중계 주소:8768**을 팀원에게 알려준다.

운영 PC만 보드의 C++ 전달기 두 개에 SSH로 연결한다. 기본 중계 포트는 TCP8768이며 실행 화면에서 변경할 수 있다.

시험 시작 전과 Pi4 플래너 연결 전에 보드 시각을 운영 노트북에 한 번 맞춘다. 센서 측정 시각 자체는 바꾸지 않는다.

## 나머지 PC는 관전

1. 같은 앱을 실행하고 **관전 · 메인 PC에서 수신**을 선택한다.
2. 운영 PC가 알려준 **주소:포트**를 입력하고 **관전 연결**을 누른다.

관전에는 보드 주소·SSH 비밀번호·ROS가 필요 없다. 시작·종료·모델 변경은 운영 PC에서만 한다. 관전은 연결 이후 궤적을 누적하며, 현재 영상·지도·상태는 메인 PC의 최신값을 받는다.

운영·관전 모두 **개발 창 → 위치추정 / 인지 / 주행가능성 / 플래닝 / 제어**를 사용할 수 있다. 창을 여러 개 열어도 같은 수신 데이터를 공유한다.

메인 창에는 **코스트맵·경사도·궤적/방위**만 나란히 표시한다. 카메라·인지 영상은 **인지 개발 창**, VIO 추적 영상은 **위치추정 개발 창**에서 확인한다. 영상·지도 미리보기는 보드 전달기에서 각각 최대 **1Hz**로 보내고, 위치 데이터 주기는 유지한다. 개발 창을 닫아도 운영 PC는 최신 미리보기를 보관해 새로 여는 창과 관전 PC에 공유한다.

주기적인 화면 PNG 저장은 기본으로 하지 않는다. 상태·실행 로그 기록은 유지한다.

## 주행 데이터 기록·재생

1. 실시간 창 상단 **기록 시작**을 누른다. 영상·지도·위치·경로·제어 상태·모듈 로그 중 이 PC가 받은 데이터를 저장한다.
2. **기록 정지**를 눌러 저장을 끝낸다. 창을 닫을 때도 기록을 마무리한다. 저장 오류·미완료 상태는 상단에 표시된다.
3. **기록 폴더**에서 `.nomad` 파일을 찾는다. 공유폴더 앱의 기본 경로는 `NOMAD_모듈별_통합_20261104/주행기록/`이며 파일명에 날짜와 시각이 들어간다. 기록 시작·기록 열기·기록 폴더·시작 창의 파일 선택은 같은 경로를 사용한다. 명시적인 `XDG_STATE_HOME`이 있으면 기존처럼 그 아래 `nomad-trial/recordings/`를 사용한다. 공유폴더 구조가 없는 Git 배포본은 `~/.local/state/nomad-trial/recordings/`로 저장한다.
4. 시작 창 또는 실시간 창에서 **기록 열기**로 `.nomad` 파일을 선택한다. 같은 GUI에서 재생/일시정지·시간 이동·0.5/1/2/4배속과 각 개발 창을 사용할 수 있다. 끝에서 재생을 누르면 처음부터 다시 재생한다.

파일 하나를 팀원에게 전달하면 같은 버전의 GUI에서 열 수 있다. 재생에는 ROS·보드 주소·SSH 비밀번호가 필요 없으며 보드 접속이나 목표·구동 명령을 하지 않는다. 원본 센서 시각은 유지하고 GUI가 적용한 수신 순서로 재생한다. 일시정지 중에는 데이터의 지연 표시 시각도 멈춘다.

이미 수신 중이던 화면에서 기록을 시작하면 그때 보이는 최신 영상·지도·상태와 메모리에 남은 궤적·로그를 시작 상태로 저장한다. 이후 데이터는 기록 시작 이후의 상대 시각으로 이어진다. 시작 전의 시간순 기록을 복원하는 기능은 아니다. 미리보기의 기존 1Hz와 위치 데이터 주기를 그대로 기록하며, 새로운 보드 구독이나 센서 원본 수집을 추가하지 않는다. 저장 파일에는 수신한 지도 이미지와 격자 위치 정보가 들어가며, GUI에 오지 않는 원본 점군·인지 라벨 배열·수치 비용 배열은 새로 수집하지 않는다.

재생 파일은 SQLite 형식이며 완전히 저장된 `.nomad` 한 개로 공유할 수 있다. 기록 중인 파일은 **기록 정지**로 마무리한 후 전달한다. 실행 중 강제 종료된 기록은 미완료로 표시하고 저장된 부분만 재생한다. 디스크 쓰기는 별도 스레드에서 처리하고 메모리 큐가 넘치면 오류를 표시한다. 비밀번호나 전체 실행 환경은 파일에 넣지 않는다.

터미널에서 기록만 열기:

```bash
/usr/bin/python3 monitor.py --replay /절대경로/기록파일.nomad
```


각 개발 창은 **왼쪽 지도·영상 / 오른쪽 실행 로그**로 나뉜다. 오른쪽 로그는 창 전체 높이를 쓰고 폭을 조절할 수 있으며 긴 줄은 자동 줄바꿈한다. 이미 수신한 로그는 노트북 메모리 버퍼에 보관하고 화면에는 **초당 한 번 새로 들어온 내용만** 추가한다. 창을 처음 열 때 최근 기록을 메모리에서 한 번 가져오며, 새 로그가 없으면 다시 훑거나 그리지 않는다. 최근 800행을 보며 검색·일시정지·자동 스크롤·표시 비우기를 사용할 수 있다. 위로 스크롤해 지난 내용을 읽는 중에는 화면이 맨 아래로 튀지 않는다. 비우기는 화면만 지우며 보드 로그 파일은 유지한다.

운영 PC만 독립 C++ 로그 도구로 초당 한 번, 보드당 최대 8KiB를 읽고 관전 PC에는 기존 중계로 전달한다. 원본 로그 전체를 전송하는 기능은 아니며, 밀린 로그는 최근 부분만 보여준다. Pi4 로그 주소는 플래닝 창의 Pi4 주소를 사용한다.

궤적 오른쪽 위의 작은 방위계는 현재 전방을 표시한다. 확인된 방위는 N/E/S/W·방위각, 미보정 지자계로 초기화한 방향은 황색 ‘임시 방위’, 북쪽 기준이 없으면 로컬 축·‘방위 미확정’을 표시한다. 추가 센서 구독은 없다.


위치추정 개발 창의 **지자계 시험**은 ZED 자기장·가속도로 별도 계산한 자북 방위를 0.5초마다 표시한다. 자기장 XYZ/세기(µT), 수신·시간 경고, 보정 상태 미확인도 함께 표시한다. 융합 출력에는 적용하지 않는다.

## 종료

- 관전 창의 X: 자기 연결만 종료.
- 운영 실시간 창의 X: 중계·화면 수신과 이 창에서 시작한 Pi4 플래너 종료. Pi5·Jetson 센서 모듈은 유지.
- 운영 PC의 **시험 종료**: Pi4 플래너 연결과 두 보드의 센서·VIO·융합·인지·지도 종료. 보드 전원은 유지.

운용 PC는 플래닝 창의 출력 허용·정지로 Pi4 출력 상태를 제어한다. 최초에는 별도 출력 허용이 필요하며, 한 번 허용하면 재계획·목표 변경에도 유지한다. 다른 PC는 운영 PC와 TCP8768로 통신할 수 있는 같은 네트워크에 연결한다. 이 버전은 읽기 전용 관전이며 로그인/암호화 기능은 없다.

## Pi4 경로 확인

1. **개발 창 → 플래닝**을 열고 Pi4 주소에 `user@lpp.local` 또는 Pi4 IP를 입력한 뒤 **플래너 연결**.
2. 큰 지도에서 목표를 클릭하고 **선택 목표 보내기**. 보라색은 Hybrid A*, 노란색은 RPP 예측 경로다.
3. 경로가 생성되면 **출력 허용**을 한 번 누른다. 재계획·목표 변경에도 허용 상태를 유지한다. **목표 취소**는 현재 주행을 중단하고, **출력 정지**·**플래너 종료**는 허용 상태도 해제한다. 관전 PC는 제어할 수 없다.

휠로 확대·축소하고 오른쪽 드래그로 지도를 이동한다. **전체보기**는 지도·차량 이동 경로·목표·GPP/RPP 경로를 모두 맞추고, **차량 중심**은 현재 배율을 유지해 차량으로 이동하며, **20m 보기**는 기본 범위를 복원한다. 지도 갱신 중에도 사용자가 조정한 범위를 유지한다. 지도 영역 밖의 목표도 같은 `odom` 좌표로 선택할 수 있다. 회색 여백은 미관측 표시이며 실제 비용지도에 주행가능 영역을 추가하지 않는다. 전용 창을 닫아도 메인 수신과 플래너는 유지한다.

GPP·LPP 상태와 원인을 따로 표시한다. LPP가 막혀도 GPP 경로는 볼 수 있으며, 점선·흐린 경로는 이전/무효 경로 참고용이다. 실행 후보 유효 여부와 실제 출력 허용은 별개다.

### 차량 윤곽과 검사 셀 (2026-11-09)

플래닝 창은 **OAK IMU 기준 앞 0.05m·뒤 0.35m·좌우 각 0.10m**인 현재 차량 검사 영역을 실제 지도 축척으로 표시한다. 청록색 사각형은 차량 윤곽, 흰색 짧은 변은 전면, 청록색 점은 OAK IMU 기준점이다. 기준점은 사각형 중심보다 전방 0.15m에 있다. 기존 카메라 전방축과 전체 자세 quaternion을 사용하므로 지도 회전 및 roll/pitch가 있는 경우도 같은 좌표로 그린다. 위치 수신이 1초 이상 지연되면 회색 점선과 STALE 표시로 마지막 위치임을 구분한다.

**차량 근접 보기 · 2m**로 확대하면 셀과의 겹침을 쉽게 확인할 수 있다. **차량 윤곽 / 검사 셀 테두리**로 표시를 끄고 켤 수 있다. 주황 점선 셀은 Pi4 `result_validation.hpp`의 보수적인 교차식에 따라 현재 차량과 겹치는 표시 지도 셀이다. 셀 중심이 사각형 밖에 있어도 셀 일부가 걸치면 검사에 포함될 수 있다. 테두리만 겹쳐 그리며 지도 색은 바꾸지 않는다. `margin: 0.10`은 제동 여유 설정이므로 이 사각형을 추가 팽창시키지 않는다.

**화면은 `/nomad/navigation_costmap` 전역 지도이며, LPP 검사는 지역 지도와 남은 예측 궤적 전체를 사용한다.** 이 표시는 현재 위치에서의 비교용이다. 주황 셀이 장애물로 확정됐다는 뜻은 아니며, JPEG 색으로 비용 80 이상을 역산하지 않는다. 현재 차량이 겹치지 않아도 미래 궤적에서 충돌할 수 있고 지도·위치 수신 시각도 다를 수 있다. 실패 순간의 지역 지도·궤적을 재현하는 기능은 아니다.

표시 치수는 `config/planning_footprint.json`에 있으며 2026-11-09 Pi4 설치 설정 `half_length=0.20`, `half_width=0.10`, `center_offset=-0.15`과 대조했다. 보드 설정 변경 시 이 파일도 맞춰야 하며 자동 동기화는 하지 않는다. 이번 치수는 Pi4 풋프린트 축소와 함께 맞췄으며 제동 마진은 0.10m를 유지한다. 변경된 GUI는 다음 실행부터 적용된다.

Pi4 실행 파일: `~/nomad_cpp_ws/src/nomad_planning_cpp/scripts/run_planning_output.sh --stdio`.
플래너 설정: `~/nomad_cpp_ws/install/nomad_planning_cpp/share/nomad_planning_cpp/config/planning_output.yaml`.
제어기 환산표: `~/nomad_cpp_ws/install/nomad_control_cpp/share/nomad_control_cpp/config/planning.yaml`.

현재는 공유폴더의 사진·영상 기반 초기 환산표를 사용하는 prototype 출력 프로필이다. 명령 속도 상한은 0.25m/s, 등가 조향각은 ±0.30rad이며 실측 속도·조향 보정 완료를 의미하지 않는다. `speed_valid`/`steering_valid`를 측정값처럼 바꾸지 않는다. Pi4에서 기존 출력 프로세스를 정리하고 driver·controller·planner를 domain59로 준비하지만, 최초 **출력 허용** 전에는 이동 명령을 내지 않는다. 한 번 허용하면 재계획·새 목표에도 유지하고, 입력·경로가 유효하지 않으면 정지했다가 회복 시 재개한다. **출력 정지** 또는 실행 세션 종료 시 허용을 해제한다. 실행 세션 종료 시 자신이 시작한 출력 프로세스도 종료한다. 하드웨어 오류·제어 명령 만료에 따른 제어기 정지는 별도 복구가 필요하다.

계산만 확인하려면 기존 `run_planning.sh --stdio`와 `planning_real.yaml`의 `plan_only=true`를 사용할 수 있다.

출력 프로필은 기존 `PlanningCostLayers`와 지역 비용지도를 사용하며, 미관측 구간 통과를 허용한다(`corridor.allow_unknown_transit: true`). 경유점은 반경 1.5m 안의 최신 전역 지도에서 관측된 주행 가능 셀(0~79)로 정한다(`corridor.waypoint_radius: 1.5`). 목표가 아직 관측되지 않으면 가까워져도 경유점 선택을 계속한다. 지역 지도의 unknown만으로 같은 경로를 다시 차단하지 않는다.

출발 시에는 첫 유효 위치의 차량 검사 영역을 고정 기준으로 삼아, 그때 이미 차지한 지도 밖 부분만 예외로 허용한다(`observed_guard.allow_initial_footprint_outside: true`). 이후 새로 진입하는 지도 밖 영역과 알려진 장애물(80 이상)은 차단한다. 계산 전용 `planning_real.yaml`의 기존 엄격한 설정은 유지한다.

입력이 없으면 ‘미수신’, 끊긴 값은 ‘오래됨’으로 표시한다. 지도 회색은 비용·경사 미확정인 곳이며 미관측만을 뜻하지 않는다. 현재 임시 장착 설정은 유지한다.

## 위치추정 모드·비교·재실행

- 메인 화면과 **개발 창 → 위치추정**에서 VIO 단독 / VIO·GNSS 융합 / GNSS 위치·지자계 방향 / 위치 입력 대기·끊김을 구분한다.
- **GNSS / VIO·로컬 비교 / 융합 위치**를 선택해 같은 로컬 차체 기준으로 비교한다. VIO 비교는 구간 시작 때 정렬한 좌표이며, 이후 GNSS 최적화로 함께 보정하지 않는다. 원본 VIO와 내부 IMU 기준 융합은 별도 선택한다.
- **지자계로 방향 초기화**는 VIO 단독 1초 유지·0.5초 정차·유효 지자계 입력 때 사용한다. 현재 차체 위치는 유지하며 방향을 맞춘다. 보정 미확인 지자계는 계속 임시 방위로 표시한다.
- **VIO 재실행**은 현재 시험의 VIO만 다시 켠다. fusion이 계속 실행 중이면 마지막 유효 위치·방향에 이어 붙인다. fusion이 없으면 원본 VIO는 새 원점에서 시작하며, 이전 위치를 복구했다고 표시하지 않는다.
- 두 버튼은 운영 PC에서만 사용하며 관전·기록 재생은 읽기 전용이다. 설정은 Pi5 `/home/user/nomad_ws/config/fusion_independent.yaml`이다.
