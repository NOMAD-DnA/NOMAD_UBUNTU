# 출력 허용 자동 기록 · 시험 종료 필수 메모 (2026-11-13)

공유폴더의 현행 GUI에 적용했습니다. 보드 코드·토픽·GPP/LPP·제어 로직은 변경하지 않았습니다.

## 사용 흐름

1. 플래너를 연결하고 목표를 보냅니다.
2. 메인 창 또는 플래닝 작업창에서 **출력 허용**을 누르면, 주행 기록을 먼저 준비하고 기존 출력 허용 요청을 보냅니다. 기록 준비 실패 시 출력 허용 요청은 보내지 않고 화면에 오류를 표시합니다.
3. 수동 기록이 이미 켜져 있으면 그 파일을 그대로 사용합니다. 출력 정지 후 재허용하거나 버튼을 다시 눌러도 같은 파일에 계속 기록합니다. 자동 기록 중에는 수동 기록 정지 버튼을 잠급니다.
4. **시험 종료**를 누르면 기존 모듈 종료 절차를 시작한 뒤 **시험 기록 작성** 팝업이 뜹니다. 입력 때문에 종료 요청을 지연하지 않습니다. 기존 SSH 인증 창이 필요한 경우에는 먼저 인증을 마쳐야 합니다.
5. **시험 이름과 시험 내용 모두 필수**입니다. 공백만 입력하면 저장할 수 없습니다. 종료 결과와 파일 마무리를 확인하면 저장 버튼이 활성화됩니다. Esc·X로 메모를 버릴 수 없고, 저장 전에는 메인 창도 닫히지 않습니다.
6. 기록 파일 오류로 메모를 넣지 못하면 **메모만 다른 위치에 저장…**으로 이름·내용·종료 결과와 기록 오류를 JSON에 보관할 수 있습니다. 누락된 주행 로그를 복구하는 기능은 아닙니다.
7. 종료 실패도 그대로 기록하며, 메모 저장 후 기존 **종료 재시도**를 사용할 수 있습니다. 재시도는 같은 파일에 종료 결과와 메모를 갱신합니다.

## 기록 내용과 위치

- 기존 수신 경로의 지도·영상·위치·GPP 경로·LPP 예측궤적·플래닝 상태/명령 값·수신된 모듈 로그·보드 부하를 `.nomad`에 저장합니다. 보드에 새 구독이나 기록 프로세스를 만들지 않습니다.
- **GUI가 실제 수신·검증한 데이터만 기록**합니다. 보드 원본 토픽 전체, 수신되지 않은 데이터, 제어기의 실측되지 않은 조향까지 보장하는 기능은 아닙니다.
- 기록 시작 직전 화면에 있던 최신 데이터와 제한된 궤적 이력은 초기 상태로 포함됩니다. 출력 허용 클릭 시각은 별도 이벤트로 남으며, 클릭이 실제 구동 성공을 뜻하지 않습니다.
- 자동 시작한 기록의 `recording_trigger`는 `output_allow`입니다. 출력을 한 번도 허용하지 않은 채 시험을 종료하면 `trial_end_without_output_allow`로 종료 시점의 상태만 저장합니다. 앞선 주행을 소급 기록한 것이 아닙니다.
- 이름·내용·종료 요청 시각·종료 결과는 **같은 `.nomad`의 metadata.user.trial**에 저장합니다. 한 파일만 복사해도 메모가 같이 이동합니다. 이름은 파일 경로로 사용하지 않습니다.
- 다시보기의 기록 표시줄에 시험 이름이 나오며, 표시줄에 마우스를 올리면 시험 내용이 표시됩니다.
- 설치된 노트북: `~/nomad_gui/주행기록/`. 공유본 직접 실행: 통합 폴더의 `주행기록/`. 명시적 `XDG_STATE_HOME` 설정과 기존 공유폴더 업로드 방식은 유지합니다.
- 일반 창 닫기는 기존대로 기록을 flush합니다. 필수 메모 팝업은 **시험 종료 버튼** 흐름에 적용됩니다. 강제 종료·전원 손실 때에는 저장된 부분만 복구 가능하며 메모 입력을 강제할 수 없습니다.

이미 실행 중인 GUI에는 즉시 적용되지 않습니다. 주행을 마친 뒤 GUI를 다시 켜고 공유폴더 업데이트를 적용하세요.
