NOMAD 실차 GUI — 선택형 RTK 보정 사용 안내
2026-11-11

1. 켜는 순서
기존 공유폴더에서 실행하던 앱을 다시 열고 운영 모드로 보드에 연결한다.
기존 '시험 시작'으로 Pi 5 GNSS를 실행한다. 이미 실행 중이면 '화면 연결 · 중계'를 사용한다.
메인 화면의 'RTK 설정 / 상태'를 누른다. 이때 Pi 5 상태 연결만 열리며 보정은 자동으로 켜지지 않는다.
'GNSS 실행 후 다시 확인하세요'가 보이면 GNSS 실행 상태를 확인한다.

서울시 기본 접속 정보:
  서버: gnss.eseoul.go.kr
  포트: 2101
  보정 채널(마운트포인트): VRS-RTCM32
  NTRIP ID: seoul
  NTRIP 비밀번호: seoul
  TLS 연결: 해제

별도 회원가입 없이 사용하는 공개 계정이다. Pi 5 SSH 계정/비밀번호와 다르다.
'접속 / 로그인 확인'을 누르고 '접속·로그인 확인 완료'를 기다린다.
이 버튼은 서버의 채널 목록과 선택한 채널 인증을 확인한다. 아직 RTCM을 수신기에 공급하지 않는다.
확인 후 '보정 시작'을 누른다. Pi 5가 현재 GNSS 위치를 서버에 보내고 RTCM 보정을 수신기에 전달한다.
인터넷 연결 구성은 별도 담당 범위이며, 여기서 보드 Wi-Fi/유선 연결을 변경하지 않는다.

2. 상태 읽기
유효한 GNSS 위치 대기: 안테나가 하늘을 보도록 설치하고 GNSS 좌표·UTC가 확정되기를 기다린다.
  위치가 없으면 VRS용 GGA를 만들 수 없으므로 보정 서버로 가짜 위치를 보내지 않는다.
연결됨 · 보정 데이터 대기: 접속/인증은 됐지만 아직 유효 RTCM이 오지 않았다.
보정 데이터 수신 중: CRC가 유효한 RTCM3 데이터를 받았다.
수신기에 전송 N B: 기존 GNSS USB 포트로 쓴 바이트다. 이것만으로 RTK FIX 성공은 아니다.
측위 일반 GNSS / DGNSS / RTK FLOAT / RTK FIXED: 수신기의 NAV-PVT 실측 상태다.
  RTK FIXED가 확인되어야 정수 모호성이 고정된 RTK 상태다. FLOAT는 미고정 상태다.
수신기 사용 보고 미확인: RXM-RTCM 출력이 꺼져 있으면 이 값은 표시할 수 없다.
  현재 수신기 설정을 강제로 바꾸지 않으며, 미확인만으로 보정 실패라고 단정하지 않는다.
추정 수평 정확도: 수신기가 계산한 hAcc이며 실제 현장 오차를 측정한 값은 아니다.
상태 오래됨 / 미확인: 마지막 화면 정보로 현재 수신 성공을 판단하지 않는다.

3. 끄기와 끊김 처리
'보정 중지'는 NTRIP 연결과 새 RTCM 공급만 멈춘다. GNSS 읽기와 주행 명령은 건드리지 않는다.
보정이 끊기면 자동 재연결한다. 오래된 보정은 재사용하지 않는다.
보정 OFF 또는 인터넷 단절만으로 주행을 멈추지 않는다. 일반 GNSS/VIO로 기존 위치추정이 유효하면 계속 주행한다.
위치추정 자체가 무효/만료되거나 기존 주행 안전 조건이 깨지면 원래 정지 조건은 그대로 적용된다.
수신기가 마지막 보정을 당분간 활용할 수 있으므로 OFF를 눌렀다고 FIX 표기를 강제로 지우지 않는다.
RTK 설정 창이나 운영 GUI를 닫아도 Pi 5 보정은 유지된다. 중지하려면 '보정 중지'를 누른다.
'시험 종료'로 GNSS가 종료되면 보정도 종료되며, 다음 GNSS 실행은 항상 OFF다.

4. 로그와 계정
RTK 창에는 연결/재연결/중지 및 측위 상태 변화 로그가 나온다.
운영 PC의 기존 '기록 시작'을 켜면 RTK 상태/이벤트도 함께 저장된다. 자동 기록을 추가하지 않는다.
관전 PC와 기록 재생은 상태만 본다. 로그인·시작·중지·SSH 연결은 하지 않는다.
입력한 설정/개인 비밀번호는 GUI와 실행 중인 RTK 작업의 메모리에만 있고 파일/주행 기록에 저장되지 않는다.
다른 NTRIP 서비스를 쓸 때는 그 서비스의 주소·포트·채널·계정을 입력하고 다시 접속 확인한다.
RTK 시작 전에 최신 프로그램이 설치된 GNSS를 실행해야 한다. 기존 GNSS 프로세스가 실행 중이었다면 다음 시험 시작 때 새 코드가 적용된다.

5. 확인 범위
서버 인증 성공, 보정 데이터 수신, 수신기 RTK FIX 성공은 서로 다른 단계다.
이 기능의 실내 검증만으로 야외 FIX나 위치 정확도, 자율주행 성공을 보장하지 않는다.
실제 FIX 확인은 안테나 하늘 시야·현재 위치·서비스/통신 상태를 갖춘 현장에서 수행한다.
