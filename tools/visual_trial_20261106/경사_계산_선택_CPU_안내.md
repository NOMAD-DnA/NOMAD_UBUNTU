# 경사 계산 방식 선택과 CPU 표시

공유 GUI의 OAK 점군 선택 아래에 경사 계산 선택을 추가한다. 기존 방식은1스레드, 병렬 방식은3스레드다. 병렬화 대상은 읽기 전용 근접점 검색과 직접 TLS 계산이다. 높이 캐시 갱신,3x3/5x5 보조 계산과 평면 반영 순서는 유지한다. 재계산 대상이32셀 미만이면 병렬 모드에서도 순차 처리한다. 동일 worker가 계산 묶음 사이에서 설정을 적용하므로 전환 자체가 지도나 첫 고정 평면을 초기화하지 않는다.

CPU 표시는 개발 창 > 인지 안에 있다. 활성 방식의 경사 worker 프로세스에 속한 모든 스레드 사용량을 약1초 간격으로 표시한다.100%는 한 코어 전체이며 병렬 처리 시100%를 넘을 수 있다. 미선택 방식은 미실행으로 표시하고 이전 측정값이 있으면 최근 값과 경과 시간을 함께 표시한다. 연결이 끊기거나3초 넘게 수신되지 않으면 실시간으로 표시하지 않는다. 두 방식을 비교하려고 두 worker를 동시에 실행하지 않는다.

CPU는 누적 실행 시간의 평균이 아니다. Linux /proc/PID/stat의 utime과 stime 차이를 SC_CLK_TCK와 단조 시계의 표본 간격으로 나눈다. PID와 시작 tick 및 boot ID를 확인하며 모드 revision이 바뀐 구간이나 프로세스 재시작 구간은 버린다. 프로세스 전체 stat을 읽으므로 개별 thread의 stat을 다시 더하지 않는다.

원본 기술 문서: https://www.kernel.org/doc/html/v6.15/filesystems/proc.html 의 Table1-4. 병렬화에 순차 부분과 준비 비용이 남는다는 원문 근거: Gene M. Amdahl, AFIPS1967, https://www.cs.cmu.edu/~18742/papers/Amdahl1967.pdf . 두 문서는 이 Jetson의 실제 지도 갱신 속도나 최적 스레드 수를 검증한 연구가 아니다.

지도 시작 전에도 경사 방식을 저장할 수 있다. 이 경우 GUI는 다음 지도 시작부터 적용한다고 표시하며 실행 확인이나 CPU0%로 표시하지 않는다. 실행 중에는 worker의 PID와 요청 revision에 대한 확인을 기다린다. 실패하면 이전 설정으로 되돌리고 확인 여부를 구분한다. 선택과 CPU 읽기 도구는 센서나 지도를 시작하지 않는다.

기본 저장 방식은 기존1스레드다. 초기1.5m/360도0도 고정, 원 밖 retry100, 초기 사람 점유 중 경사 비용-1 및 실제 LiDAR 광선 후0 복원,12.5cm 격자와18.75cm 검색 반경 및 의미 비용 융합은 마지막 배포본과 같다. 별도 대화의 semantic-majority-watch 다수결과 점 분포 로그는 포함하지 않는다.

경사 CPU 표시의 범위는 경사 worker이며 카메라, 인지 모델, Mapper 부모, 전체 Jetson의 CPU와 다르다. 모드 비교 시 입력, 재계산 대상 셀과 다른 작업의 부하가 달라질 수 있으므로 두 순간의 숫자만으로 성능 우열을 확정하지 않는다.
