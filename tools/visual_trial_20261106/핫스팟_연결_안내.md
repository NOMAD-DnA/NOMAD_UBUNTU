# 교실 Wi-Fi와 노트북 핫스팟

2026-11-11 / 기능 ID `nomad-gui-laptop-wifi-20261111-1`. 2026-11-10의 300초 확정 전환 기능(`nomad-gui-hotspot-20261110-1`)을 대체한다.

휴대폰 핫스팟은 연결된 기기끼리의 통신을 막아 보드 사이 ROS 통신이 되지 않았다. 그래서 우분투 노트북의 핫스팟을 보드용 망으로 쓰고, 인터넷이 필요하면 그 노트북에 휴대폰을 USB 테더링으로 연결한다.

## 동작 방식

- 보드는 평소 **교실 Wi-Fi**에 붙는다.
- 등록한 **노트북 핫스팟**은 보드에 예비 Wi-Fi로 저장된다. 노트북마다 하나씩, 자동 연결, 재시도 무제한, 교실 Wi-Fi보다 낮은 우선순위, 고정 주소 Pi4 `.14`, Pi5 `.15`, Jetson `.16`(노트북이 `10.42.0.1`이면 `10.42.0.14/15/16`).
- **야외**: 교실 Wi-Fi가 없으니 보드가 저장된 노트북 핫스팟에 스스로 붙는다. 노트북 하나가 꺼지면 다른 등록 노트북의 핫스팟을 켜면 그쪽에 붙는다.
- **실내 시험**: GUI의 **실내 시험 시작**이 8초 뒤 교실 Wi-Fi 연결을 끊는다. 보드는 노트북 핫스팟으로 옮겨간다. **교실로 복귀**는 8초 뒤 교실 Wi-Fi에 다시 연결한다.
- **안전장치**: 보드의 Wi-Fi 연결 없음이 설정 시간(기본 120초, 30~900초) 이상이고 교실 Wi-Fi가 보이면 교실 Wi-Fi로 돌아간다. 야외에서는 교실 Wi-Fi가 안 보여 동작하지 않는다.
- Pi5와 Jetson은 기동할 때 자기 wlan0 주소가 노트북 대역이면 Pi4의 노트북 고정 주소를, 아니면 교실 주소를 플래닝 통신 대상으로 쓴다(`/etc/nomad/network-peers.json`).

## 규칙

- **핫스팟은 한 번에 노트북 하나만 켠다.** 두 대가 동시에 켜면 보드가 서로 다른 노트북에 나뉘어 붙을 수 있다.
- 모든 노트북 핫스팟은 같은 대역을 쓴다. 우분투 핫스팟 기본값 `10.42.0.1/24`를 권장한다. GUI의 **새 핫스팟 만들기**는 이 값과 2.4GHz로 만든다.
- 시험 중에는 핫스팟 노트북의 절전을 끈다. 노트북이 꺼지면 보드끼리 통신이 끊긴다.
- 보드 간 통신이 확인되기 전에는 출력 허용을 누르지 않는다.
- Pi5와 Jetson 사이 직결 LAN은 그대로 쓴다.

## 처음 한 번 (교실 Wi-Fi에서)

1. GUI 첫 화면 **Wi-Fi / 노트북 핫스팟**을 연다. 보드 주소와 **공통 SSH 비밀번호**(보드의 sudo에도 쓴다)를 넣는다.
2. **보드 기능 설치 / 기존 300초 기능 정리**를 누른다. 세 보드에 새 기능과 안전장치 서비스를 설치하고, 예전 전환 기능과 `nomad-gui-*`, `nomad-hotspot-*` 프로필(예: `8064`)을 지운다. 지금 연결은 바꾸지 않는다. 이때 연결된 Wi-Fi를 교실 Wi-Fi로 기록한다.
3. **이 노트북 핫스팟**에서 프로필을 고르거나 **새 핫스팟 만들기**로 만든다(꺼진 상태로 만들어짐).
4. **이 노트북 핫스팟 정보 넣기** → SSID, 비밀번호, 노트북 주소가 채워진다. 노트북 이름을 확인하고 **보드에 등록**을 누른다.
5. 다른 노트북도 그 노트북에서 GUI를 열어 같은 방법으로 등록한다.

## 실내 시험

1. 교실 Wi-Fi에서 **현재 상태 확인**으로 세 보드가 `교실 Wi-Fi`이고 노트북이 등록돼 있는지 본다. 처음이면 **교실 주소를 GUI·보드에 적용**도 누른다.
2. **실내 시험 시작**. "예약 뒤 이 노트북 핫스팟 켜기"가 체크돼 있으면 이 노트북 핫스팟을 켜고 GUI 주소를 노트북 고정 주소로 바꾼다. 이 노트북은 교실 Wi-Fi가 끊긴다.
3. 수십 초 뒤 **현재 상태 확인**으로 세 보드가 `노트북 핫스팟`인지 본다. 창을 닫고 **시험 시작**.
4. 끝나면 **교실로 복귀**. "핫스팟 끄기"가 체크돼 있으면 이 노트북 핫스팟도 끈다. 이 PC가 교실 Wi-Fi로 돌아오면 **저장된 교실 주소 넣기** → **현재 상태 확인** → **교실 주소를 GUI·보드에 적용**.

다른 PC가 GUI를 돌리고 핫스팟 노트북이 따로 있으면, 핫스팟은 그 노트북에서 켜고 GUI PC는 같은 핫스팟에 접속한 뒤 **노트북 주소를 GUI에 적용**을 누른다.

## 야외

핫스팟 노트북의 핫스팟을 켜고 보드를 켠다. 보드가 스스로 붙는다. GUI에서 **노트북 주소를 GUI에 적용** 후 시험을 시작한다.

## 실패와 복귀

- 실내 시험 시작 뒤 노트북 핫스팟이 켜지지 않으면, 안전장치 시간이 지나 보드가 교실 Wi-Fi로 돌아온다.
- 한 보드만 예약에 실패하면 GUI가 알린다. 상태 확인 후 **교실로 복귀**를 누른다.
- 모든 방법이 실패하면 보드를 재부팅한다. 재부팅하면 교실 Wi-Fi가 우선이다.

## 저장 위치

- 보드 기능: `/usr/local/lib/nomad-network/wifi_agent.py`, 안전장치 서비스 `nomad-wifi-watchdog.service`
- 설정: `/etc/nomad/laptop-wifi.json`(교실 Wi-Fi 기록, 안전장치 시간), `/etc/nomad/network-peers.json`(교실·노트북 주소)
- 노트북 프로필: `/etc/NetworkManager/system-connections/nomad-laptop-<이름>.nmconnection`(root 전용 0600, 핫스팟 비밀번호 포함)
- GUI: `~/.local/state/nomad-trial/boards.json`(현재 주소), `network_sets.json`(저장된 교실 주소)
- 수동 설치: 보드에 `laptop_monitor/board_network`를 복사하고 `bash board_network/install.sh`

SSH와 핫스팟 비밀번호는 PC 설정, 명령행 인자, 로그에 저장하지 않는다. 단, **새 핫스팟 만들기**는 이 노트북의 nmcli에 비밀번호를 인자로 넘긴다(그 순간의 로컬 프로세스에만 보인다).

- PC 오프라인 검사: 보드 기능 14개(가짜 NetworkManager), 통신 6개, 연결 창 12개, 기동 스크립트 주소 선택 6개, 기존 검색 2개. GUI 전체 254개 통과.
- 세 보드의 Python(3.10 / 3.12 / 3.8)에서 새 기능 컴파일과 사용하는 nmcli 조회 명령을 읽기로 확인했다.
- 실제 설치, 실내 전환, 야외 자동 연결, 안전장치 복귀, 노트북 핫스팟에서의 ROS 연동은 아직 실물로 확인하지 않았다.
