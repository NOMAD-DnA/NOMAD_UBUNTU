## 2026-11-16 추가 기능

버튼 이름은 공유 GUI 코드(`laptop_monitor/`)에서 그대로 옮겼다. 대부분 테스트만 통과했고 **실차 미확인**이다.

### 설치·업데이트

```bash
# 노트북에서: 공유 원본 → ~/nomad_gui 설치·업데이트
bash /home/user/samba/shared/NOMAD_모듈별_통합_20261104/NOMAD_실물시험앱_20261106/GUI_설치_업데이트.sh
```

설치 뒤 앱 "NOMAD GUI (로컬)"로 켠다. 공유폴더가 보이면 켤 때 새 버전 업데이트를 묻는다. 업데이트 안 한 노트북은 11-16 기능이 없다.

### 시험 설정 창 (`시험 설정` 버튼)

**지도(매퍼) 선택** — 시작 전에 하나 고른다. 기본은 `기존 매퍼`.

| 목록 이름 | 설정 버튼 | 바꾸는 값 |
|---|---|---|
| 기존 매퍼 | 없음 | — |
| 기존 매퍼 개선 (단일 프로세스) | `기존 매퍼 개선 설정…` | 지도 크기·경사 각도 기준·경사 고정·의미분할 누적·경사 점수 계수 k·클래스 경계 px·초기 안전영역 |
| 새 매퍼 (높이 지도 · 시험용) | `새 매퍼 세부 설정…` | 공통·A 높이·B 의미·C 점수(경사 k 포함) |
| 새 매퍼3 v3 (경사 정확도·넓이 개선) | `새 매퍼3 v3 설정…` | 클래스 경계 px·초기 안전영역 반경·경사 점수 계수 k |

- 값은 Jetson에 저장되고 **시작할 때** 적용된다. 프리셋은 `표에 불러오기`, `지금 표를 프리셋으로 저장…`.
- 경사 k 기본 4. 기존 개선·새 매퍼는 막힘 각 80/k°(k=4 → 20°). v3는 막힘 100/k°(기본 25°).
- 11-16에 따로 있던 '매퍼 설정' 창은 없앴다. 그 값은 위 개선 설정·v3 설정 창으로 옮겼다.
- `플래너 세부 설정…`: Jetson 플래너 값. 플래너 연결 때 적용.

**모듈 세부 설정** — 같은 창 아래 줄 버튼 5개.

| 버튼 | 보드 | 적용 시점 |
|---|---|---|
| `VIO(Basalt)…` | Pi5 | 다음 시작·VIO 재시작부터 |
| `위치 융합…` | Pi5 | 다음 시작부터 |
| `GNSS 수신…` | Pi5 | 다음 시작부터 |
| `OAK·점군…` | Jetson | 다음 시작부터 |
| `인지…` | Jetson | 다음 시작부터 |

- 바꾼 값만 보드 `~/nomad_settings/<모듈>/`에 저장된다. 보드 원래 설정 파일은 그대로다.

**설정 창 '읽는 중'** — 설정 창은 보드 값을 읽는 동안 "…에서 값을 읽는 중… (보드가 없으면 최대 수십 초)"를 띄우고 잠시 비활성이 된다. 앱 전체가 멈추지 않는다. 보드 주소가 틀리면 오래 걸린다. 먼저 `보드 찾기`를 한다.

### 시험 시작 — Wi-Fi 절전 끄기

- `시험 시작` 때 Pi5·Jetson·Pi4의 Wi-Fi 절전을 끈다. 진행 줄에 "보드 Wi-Fi 절전 끄기 (이번 부팅 동안)"가 뜬다.
- 이번 부팅 동안만이다. 재부팅하면 원래대로다. 설정 파일은 바꾸지 않는다.
- 실패해도 "Wi-Fi 절전 끄기 실패: … · 시작은 계속합니다."만 뜨고 시작은 이어진다.
- Pi4도 공통 비밀번호로 sudo가 된다는 가정은 실차 미확인.

### 목표 x·y 입력 (실시간 화면 플래닝 줄)

1. `odom x/y` 두 칸에 목표 좌표를 m 단위로 넣는다.
2. `좌표로 목표 지정` → 선택 목표가 된다. 아직 보내지 않는다.
3. `선택 목표 보내기`로 보낸다.

- 좌표는 현재 odom 기준이다. VIO 재시작·방향 초기화 뒤에는 다시 확인한다.
- 개발 창 → 플래닝에도 같은 `좌표로 목표 지정`이 있다. 관전 PC에서는 막혀 있다.

### 시험 종료 — 남은 모듈 표시

- `시험 종료`는 Pi5·Jetson 시험 모듈을 끄고, 남은 프로세스를 INT → TERM → KILL 순으로 정리한다. 센서 녹화는 보호한다.
- 그래도 남은 것이 있으면 상태 줄에 "· 남은 모듈 이름:pid"가 붙는다. 이 표시가 보이면 다시 시작하기 전에 확인한다.

### 보드 전원 끄기 (`보드 전원 끄기` 버튼)

1. 확인 창에서 끌 보드를 고른다. Pi4(팀원 보드)는 기본으로 꺼져 있다(체크 해제).
2. `전원 끄기` → 먼저 시험 모듈을 종료하고, Pi4 → Pi5 → Jetson 순으로 끈다.

- 노트북은 꺼지지 않는다. 다시 켜려면 보드 전원을 직접 넣는다.
- 센서 녹화 중이면 끄지 않는다. 차가 멈춰 있는지 먼저 본다.
- sudo 비밀번호가 필요하다(SSH 비밀번호 칸).
- 11-16 19:0x 실사용 1회: 세 보드 모두 응답 없음(꺼진 것으로 보임). LED는 미확인.

### 주행기록 올리기

- 로컬 GUI를 켤 때 공유폴더에 연결되면, 업데이트 확인 다음에 "주행 기록 올리기" 질문이 뜬다.
- `예` → 공유폴더에 없는 로컬 기록을 `주행기록/`으로 복사한다. 로컬 원본은 남는다.
- 결과는 "N개 복사했습니다." 또는 "N개 복사, M개 실패(파일: 사유)".
- 11-16 수정: 이전에는 `.nomad.part`로 남고 "0개 복사"로 나왔다. 지금은 크기 확인 뒤 이름을 바꾸고, 실패하면 사유를 보여준다. 공유폴더의 `.part` 24개는 복구했다.

## 이전 기준 (2026-11-09 작성) — 기록 보존

메인 창은 코스트맵·경사도·궤적/방위만 표시한다. RGB·인지 영상은 인지 창, VIO 추적 영상은 위치추정 창에서 확인한다. 표시용 영상·지도는 보드 전달기에서 각각 최대1Hz, 위치 데이터 주기는 그대로다.

실행:

```bash
bash 실행.sh
```

- 운영 PC: **운영 · 보드 연결 / 관전 중계** → 보드 찾기·비밀번호 입력 → **시험 시작**. 센서가 이미 실행 중이면 **화면 연결 · 중계**.
- 관전 PC: **관전 · 메인 PC에서 수신** → 운영 PC 주소와 포트 `8768` 입력 → **관전 연결**.
- 개발 창: **위치추정 / 인지 / 주행가능성 / 플래닝 / 제어**. 같은 수신 데이터를 공유한다.

제어 창은 출력 허용·차단 사유와 요청/목표/출력/측정 ERPM을 왼쪽, 제어기·VESC 로그를 오른쪽에 표시한다. 로그는 최대1Hz이며 플래닝 창과 같은 수신을 공유한다. 서보 등 제공되지 않는 값은 미수신으로 표시한다.

플래닝:

1. **개발 창 → 플래닝**에서 Pi4 `user@lpp.local` 또는 실제 IP 입력 → **플래너 연결**.
2. 지도에서 목표 선택 → **선택 목표 보내기**. GPP와 LPP의 상태·실패 원인을 각각 확인한다.
3. 최초에는 **출력 허용**을 별도로 한 번 누른다. 이후 재계획·새 목표에도 허용 상태를 유지한다. 입력·경로가 유효하지 않으면 정지하고, 회복되면 재개한다.
4. **목표 취소**는 현재 주행을 중단한다. **출력 정지 / 플래너 종료**는 허용 상태도 해제한다. 하드웨어 오류·제어 명령 만료에 따른 제어기 정지는 별도 복구가 필요하다.

보라색은 GPP, 노란색은 LPP 예측 경로다. 오래되거나 무효인 GPP는 참고용 점선으로 남고 실행 가능 여부는 따로 표시한다. 관전 PC는 조작할 수 없다.

운영 창 X는 화면·중계와 이 창에서 시작한 Pi4 플래너를 종료한다. **시험 종료**는 Pi5·Jetson 센서·모듈도 종료하며 보드 전원은 유지한다. 관전 창 X는 자기 연결만 닫는다.

설정:

- Pi4 플래너: `~/nomad_cpp_ws/install/nomad_planning_cpp/share/nomad_planning_cpp/config/planning_output.yaml`
- Pi4 제어 환산표: `~/nomad_cpp_ws/install/nomad_control_cpp/share/nomad_control_cpp/config/planning.yaml`
- 전방 표시: `config/oak_basalt_calib.json`
- 팀원 GUI 수정 위치·정책 설명: `laptop_monitor/README.md`

명령 상한은 현재 명목 0.25m/s·등가 조향각 ±0.30rad이며 실측 보정 완료값은 아니다. 업데이트는 GUI를 다시 실행하고 Pi4 플래너를 다시 연결하면 적용된다. 앱 목록 등록은 `bash 앱등록.sh`.
